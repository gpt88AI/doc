If you allow it, we analyze only the documentation page, campaign, and Agent entry click to improve the docs and setup flow. The optional analytics event payload contains no email, prompts, API keys, tokens, account, device, or browser identifiers. Basic request metadata is used only for security and rate limiting, not analytics profiling.

Opentu 开图功能全解析：把 AI 创作、画布和任务管理放在一起

AI工具指南2026-10-0914 मिनट पढ़ेंOpentu开图AI图片生成AI视频生成无限画布流程图思维导图知识库

本文根据 Opentu 工作台 与 Opentu 用户手册 当前公开页面整理，页面与模型能力会随版本、账号权限和服务状态变化。文中把“页面列出的能力”和“适合怎样使用”分开描述，不把示例模型、分辨率或后台行为写成固定承诺。

很多 AI 工具只解决一个动作：输入提示词，得到一张图片，或者打开一块白板，手动画几个框。Opentu（开图）的定位更像一个以画布为底座的 AI 工作台：图片、视频、流程图、思维导图、素材、知识和任务都围绕同一个项目展开。

它适合的不是“只想临时生成一张图”的单点需求，而是需要边生成、边编辑、边整理，最后还要导出和归档的人。你可以先在画布里搭结构，再用 AI 补充视觉资产；也可以先生成一组图片，再把结果放进画布、素材库和任务队列，继续完成后续工作。

先看功能地图

能力组主要功能更适合解决的问题
AI 创作AI 图片生成、灵感创意板、智能拆分图片、AI 视频生成从想法得到图片、短视频或一组可发布素材
画布与图解无限画布、插入内容、画笔、形状、文本、思维导图、流程图把零散想法变成可视化结构和方案
工作流工具箱、Skill/Agent、知识库、命令面板、任务队列让提示词、资料、任务和结果可以复用、追踪和交接
资产管理图片预览与编辑、素材库、导出与导入继续修改已有结果、整理素材、备份项目和迁移数据
接入与稳定性API 配置、设置、问题排查让模型连接、浏览器数据和失败任务可检查、可恢复

一、AI 创作：从描述到可交付素材

1. AI 生成图片

这是 Opentu 最直接的入口：在画布底部输入主体、场景、构图和风格，选择当前账号可用的图片模型，提交任务后在任务队列查看状态，完成后预览、插入画布、进入素材库或下载。

应用场景： 商品图、营销海报、社交媒体配图、头像、封面、概念草图、参考图和批量视觉变体。

适合人群： 内容创作者、运营、设计师、独立开发者、小团队营销人员，以及需要快速验证视觉方向的产品经理。

需要更强控制时，可以加入参考图、指定画面比例或批量提交提示词。实际可用的模型、尺寸、权限和计费以当前工作台和 GPT88 模型页面为准。第一次使用建议先用一个简单提示词和默认尺寸完成小任务，确认链路可用后再扩大批量。

2. 灵感创意板

灵感创意板把常见创作任务做成模板或预填提示词。它的价值不是替你决定最终画面，而是让空白画布有一个可修改的起点：先选场景，再改主体、风格、尺寸和参考图。

应用场景： 不知道从哪里开始写提示词、需要快速试几种视觉方向、为海报或商品图建立第一版草稿。

适合人群： 提示词经验较少的新手、需要快速出方向的运营人员、做创意发散的设计师和需要带着团队讨论视觉方案的人。

模板只是起点。生成后仍要核对构图、文字、主体比例和版权风险，并保存真正有效的提示词、模型、比例与用途，才能形成可复用流程。

3. 智能拆分图片

智能拆分图片适合先生成一张完整画面，再按网格拆成多个小块。例如先做一张适合连续观看的整图，再拆成 2×2、3×3 或其他网格。需要注意，生成“九宫格效果图”和导出九个独立文件不是同一件事，发布前要逐块检查和保存。

应用场景： 朋友圈九宫格、系列社媒图片、拼图、连续画面、把一张大图拆成多张内容卡片。

适合人群： 社媒运营、个人创作者、电商和品牌团队，以及需要一次准备一组连续视觉素材的人。

拆分前要给主体留出足够边距，避免文字或人物正好落在切割线上；拆分后要按顺序检查每一块的边缘、清晰度和发布顺序。

4. AI 生成视频

手册将视频生成拆成文字转视频、图片转视频和首尾帧控制等路径。实际使用时，先确认当前模型支持的参考图、时长、比例和音频能力，再提交任务，在任务队列中追踪进度，完成后把结果放回画布、素材库或本地文件。

应用场景： 社交媒体短视频、产品动态展示、分镜预演、静态图片动效化、广告创意验证和视觉概念演示。

适合人群： 短视频创作者、品牌运营、广告和内容团队、产品设计师，以及需要快速验证运动方向的创意人员。

视频任务通常比单张图片更耗时。不要在任务没有明确结束前重复提交；先记录任务 ID，检查状态和错误，再决定是否重试。模型名称、时长、首尾帧和声音支持以当前模型说明为准。

二、画布与图解：把想法变成结构

5. 画布操作：无限画布与基础操作

画布是 Opentu 的组织底座。手形工具用于移动视野，选择工具用于操作元素；用户可以缩放、框选、多选、复制、撤销和重做，把图片、文字、形状和图解放在同一空间里。

应用场景： 整理多个创意版本、搭建项目白板、把图片与说明放在一起、做方案评审和保留中间过程。

适合人群： 视觉创作者、产品经理、教师、研究人员、团队协作者和不喜欢在多个窗口之间切换的人。

6. 插入内容到画布：图片、文字和形状

本地图片、生成结果、文本框、矩形、椭圆和箭头都可以成为画布元素。插入之后可以移动、缩放、旋转、对齐或组合，适合把“素材”和“解释”放在同一张工作板上。

应用场景： 方案草图、产品结构、活动排版、截图标注、图片说明、流程节点和视觉参考板。

适合人群： 需要快速排版的运营和设计人员、做产品方案的经理、教师和需要向他人解释复杂内容的人。

7. 画笔工具、形状工具与文本工具

画笔适合手绘、圈重点和做快速标注；形状与箭头适合搭建结构；文本工具负责标题、注释和节点说明。三者组合起来，能覆盖从随手草图到较正式图解的多个阶段。

应用场景： 课堂讲解、设计批注、会议讨论、界面评审、流程节点和简单的视觉笔记。

适合人群： 教师、顾问、产品和设计团队、需要远程讨论的项目组，以及偏好手绘表达的创作者。

8. 思维导图

思维导图可以从中心主题开始手动扩展，也可以让 AI 先生成结构，再逐项校正。手册还提供从 Markdown 大纲转换导图的路径，因此适合把已有的文字资料快速变成层级结构。

应用场景： 选题发散、产品需求拆解、课程大纲、项目规划、会议纪要和知识整理。

适合人群： 产品经理、项目负责人、学生和教师、内容策划、研究人员，以及需要先看整体结构再深入细节的人。

AI 生成的节点仍需要人工核对。导图可以帮助整理思路，但不能自动证明每个节点都是事实。

9. 流程图

流程图支持自然语言生成、Mermaid 转换和手动绘制三种思路：自然语言适合快速得到草稿，Mermaid 适合明确节点与连线，手动绘制适合做最后的布局和分支调整。

应用场景： 业务流程、用户路径、审批链路、技术架构草图、排障步骤和团队 SOP。

适合人群： 产品经理、研发、运营、咨询顾问、项目管理者和需要让团队对“先后顺序与判断分支”达成共识的人。

画完后要沿每一条分支从入口走到出口，检查遗漏路径、死循环、方向错误和没有标签的判断，不能只因为图形看起来整齐就认为流程正确。

三、工作流：让结果能够被追踪和复用

10. 工具箱与 Skill/Agent

工具箱把提示词参考、动作参考、聊天、单图生成、批量出图、视频和知识管理等能力集中起来；Skill/Agent 则适合把某个场景的角色、输入、步骤和输出格式固定下来。不同版本的工具名称和入口可能变化，当前工作台不可见的功能不能直接按旧教程推断。

应用场景： 复用品牌提示词、批量生产同类素材、把固定步骤做成工作流、将项目规范沉淀为可调用的操作模板。

适合人群： 有重复生产需求的运营和设计团队、需要统一输出格式的组织、熟悉 AI 工作流的高级用户和希望把经验沉淀下来的独立开发者。

适合先把流程写成“角色、输入、输出、验收条件和失败处理”，再在小任务中验证；不要把未经验证的生成结果直接固化为团队规范。

11. 知识库

知识库提供目录、标签、检索、Markdown 笔记和导入导出能力，也可以整理项目资料、提示词规范和自定义 Skill。它让画布之外的背景资料有一个长期存放的位置，并能在下一次创作时被重新找到。

应用场景： 产品资料库、品牌规范、提示词库、研究笔记、项目知识、团队 SOP 和 Skill 管理。

适合人群： 需要长期积累资产的创作者、内容团队、产品与研发团队、教师和经常重复使用资料的个人用户。

知识提取或 AI 归纳后的内容要逐条检查来源与范围。知识库适合保存可复用上下文，不适合保存 API Key、Cookie 或未经脱敏的客户数据。

12. 任务队列

任务队列负责处理异步生成：查看生成中、失败和已完成任务，按图片或视频筛选，读取错误信息，插入画布、下载、重试或批量处理。它把“提交请求”与“交付结果”分成两个可以追踪的状态。

应用场景： 批量出图、长时间视频任务、多版本提示词对比、失败任务排查和历史结果回看。

适合人群： 批量生产素材的运营和设计团队、需要管理多项异步任务的创作者、产品测试人员和需要减少重复提交的人。

重试前先确认不是重复提交、权限失败、余额不足或参数不支持。完成一批任务后抽查文件是否可打开、尺寸是否正确以及是否出现重复结果。

13. 命令面板

命令面板通常可以用 Cmd + K 或菜单打开，通过搜索功能名称直接执行操作。它的价值在于减少寻找入口的时间，尤其适合工具很多、菜单层级较深的项目。

应用场景： 快速打开任务队列、素材库、导出工具和设置，或者在忘记某个功能位于哪个菜单时直接搜索。

适合人群： 高频使用者、熟悉键盘操作的设计和研发人员、需要快速切换多个工具的专业用户。

命令面板会直接触发操作，删除素材、清空画布和清理数据前要先看确认提示。命令不存在时，可能是当前版本或权限没有提供该功能。

四、资产管理：从生成结果走到交付

14. 图片预览与编辑

图片预览适合查看原始大小和细节，编辑功能覆盖裁剪、去白边、滤镜、亮度、对比度、饱和度、色温与锐化等常见调整。保存时可以覆盖原图、另存为新版本或下载到本地。

应用场景： 生成图二次构图、去除多余边缘、准备不同社媒比例、统一一组图片的视觉效果和交付前检查。

适合人群： 运营和设计人员、电商团队、社媒创作者，以及希望在同一个工作区完成轻量修图的人。

重要图片先使用“另存为”保留原始版本。导出前同时查看原始大小和目标尺寸，检查文字清晰度、裁剪边缘和色彩。

15. 素材库

素材库集中管理上传和生成的图片、视频，支持筛选、搜索、预览、插入画布和复用参考图。它承担的是“结果沉淀”角色，而不是一次性下载后的临时文件夹。

应用场景： 管理品牌素材、复用参考图、回看历史生成、按项目整理图片和视频、让同一套素材服务多次创作。

适合人群： 有持续内容产出的个人创作者、品牌与电商团队、需要管理多版本视觉资产的设计人员。

手册说明素材与项目数据主要保存在当前浏览器。清除网站数据、换浏览器或使用隐私模式前，先完成备份并抽查恢复结果。

16. 导出与导入

导出功能覆盖 PNG/JPG 图片、可继续编辑的 .drawnix 项目文件，以及用于备份和恢复的 ZIP。图片用于发布，项目文件用于继续编辑，备份包用于迁移，三者用途不同。

应用场景： 发布图片、交付项目源文件、换浏览器或设备、保存提示词历史、迁移素材和建立阶段性备份。

适合人群： 所有长期使用者，尤其是需要交付源文件、跨设备工作或管理重要项目的团队。

自动保存不等于跨设备同步。重要里程碑应手动导出项目和备份；分享前移除不应公开的素材、提示词和凭证。

五、接入与稳定性：把边界搞清楚

17. GPT88 API 配置与首次生成

设置用于管理供应商、接口类型、图片接口格式、API 地址、API Key、模型预设、画布显示、主题、语言和移动端相关偏好。GPT88 图片模型与标准文本 API 的地址不同，配置时需要按当前文档和实际模型协议填写。

应用场景： 第一次接入模型、切换供应商、保存常用模型组合、调整主题和画布偏好、排查生成入口看不到模型的问题。

适合人群： 第一次使用 OpenTu 的用户、需要自带 API 配置的创作者、需要管理多个模型预设的高级用户和负责团队接入的技术人员。

建议先保存配置，再加载少量模型，用一个最小任务验证“模型可见、任务有状态、结果能打开”三件事。API Key 是账户凭证，不要写进公开笔记、截图、项目文件或文章示例。

18. 设置与配置

设置页除了供应商和模型，还用于调整画布显示、主题、语言和语音播放等偏好。移动端使用时，要重新确认文本输入、选择、缩放和导出是否符合当前设备的交互方式。

应用场景： 保存常用模型预设、切换明暗主题、调整画布显示、适配移动端，以及在换浏览器前确认数据和配置边界。

适合人群： 需要长期使用工作台的个人用户、管理多个创作环境的专业用户和负责团队接入体验的技术人员。

浏览器本地数据与 API 凭证的管理边界不同。清理网站数据前先备份项目、素材和知识库；API Key 应在控制台或凭证管理处处理，不要把它当普通画布数据分享。

19. 问题排查

问题排查覆盖生成失败、页面空白、素材不显示、数据丢失和视频任务长时间等待。最短路径是记录 URL、浏览器、时间、模型、任务 ID 和错误码，再检查网络、Key、端点、模型权限、余额和浏览器存储。

应用场景： 401/403、模型可见但生成失败、任务长时间没有变化、换浏览器后素材不见、页面加载异常。

适合人群： 所有使用者；其中批量生产团队、技术支持人员和需要稳定交付的专业用户更需要掌握这套排查方法。

不要在错误原因不清楚时连续重试，也不要把完整 Key、Cookie、请求头或未脱敏日志提交给他人。先备份，再清理缓存或恢复数据。

最短成功路径：先做出一个可验证的结果

第一次使用时，不建议一上来把所有功能都打开。可以按这条路径完成一个小项目：

  1. 打开 Opentu 工作台，确认当前版本和登录/配置状态。
  2. 按账号权限完成供应商、API 地址和模型配置；如果已经配置好，直接进入画布。
  3. 用一个明确提示词生成一张图片，或用一个主题创建思维导图。
  4. 在任务队列确认任务状态和结果，不要只看页面是否出现了加载动画。
  5. 把结果插入画布，补充文本、箭头或流程节点，检查布局和内容。
  6. 将需要复用的结果放进素材库，重要提示词和项目资料放进知识库。
  7. 用 PNG/JPG 导出交付图；需要继续编辑时保存 .drawnix，重要项目再做一次备份。

这条路径的验收标准很简单：模型可选择、任务有明确状态、结果可以打开、画布内容可编辑、导出文件可用、重要数据有备份。

最后判断：Opentu 适不适合你？

如果你只需要偶尔生成一张图片，Opentu 的画布、素材、任务和知识能力可能显得偏完整；但如果你的工作经常经历“想法 → 结构 → 素材 → 修改 → 交付 → 复用”，它的价值就不只是模型入口，而是减少工具切换，把过程留在同一个工作空间里。

它尤其适合四类人：需要持续生产内容的创作者，需要把方案可视化的产品和运营人员，需要管理图片与视频资产的设计/品牌团队，以及想把提示词、资料和重复流程沉淀下来的个人或小团队。

真正开始使用之前，只需要记住三件事：模型能力以当前账号与版本为准；浏览器本地数据要主动备份；生成结果、知识库内容和对外发布物都要经过人工检查。

进一步操作可直接查看Opentu 用户手册，或进入Opentu 工作台开始一个小项目。
