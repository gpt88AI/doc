21 个题材的 AI 漫剧 Skill：一句点子如何拆成五阶段制作文档

AI 视频2026-11-0113 मिनट पढ़ेंAI漫剧Agent Skill分镜剧本提示词短剧内容一致性

本文依据 zhanghao123vip/ai-manju-skills 的 README 与“现代重生复仇”题材的 SKILL.md 整理，整理时间为 2026 年 11 月 1 日。仓库采用 MIT 许可，包含 21 个题材模板。本文重点核对了 README 和其中一个代表性模板；其他题材共享总体结构，但节奏、默认值、内容尺度和提示词细节可能不同。模板本身不生成图片或视频，只产出企划、资产提示词、剧本、分镜和发布文档，实际画面仍要交给生图、视频、配音和剪辑工具完成。

AI 漫剧的常见做法是：先让模型写一个故事，再让它生成角色图，接着做分镜、生成视频，最后剪辑发布。每一步都能跑通，但到了第 10 集、第 20 集，人物脸变了、服装串了、道具位置不对、上一集的伏笔忘了回收，返工成本会迅速上升。

ai-manju-skills 试图把这些问题前置到文档阶段。它不是一个新的生成模型，而是一组按题材拆分的 Agent Skill：用户给一句故事点子，模板按阶段产出立项卡、企划案、资产库、分集剧本、导演手册和发布包。每个题材一个 SKILL.md，不需要安装依赖，可以复制到 Claude Code、WorkBuddy，或直接粘贴进 DeepSeek 等聊天工具。

21 个题材，共用一套生产结构

仓库按四类题材组织：

分类题材
幻想玄幻修仙、西幻魔法、星际机甲、系统无限流、末日废土
古代穿越重生、宫斗、宅斗、权谋朝堂、武侠江湖、种田经商
现代都市逆袭、总裁甜宠、家庭伦理、重生复仇、职场商战、年代文、娱乐圈、大学校园青春
类型片悬疑刑侦、民俗怪谈

每个题材的模板约 20KB，内容不是一段通用提示词，而是包含该题材的默认参数、节奏建议、人物和场景规范、内容尺度与示例。以“现代重生复仇”为例，默认第一季 30 集、每集约 4 分钟、9:16 竖屏 1080×1920、24fps、现代写实国漫风格；单集镜头不固定，通常 32–44 镜，每镜 3–9 秒。用户可以在点子里改写这些默认值。

题材差异体现在节奏上。重生复仇模板明确要求“今生快、前世慢”：前世闪回用长镜和低饱和冷调，今生反击干脆利落，一句台词接一个反应。其他题材会有自己的开场方式、冲突结构和视觉基调，不能直接把一套模板套到所有故事上。

五阶段：从一句点子的可交付文档

模板把生产拆成五个阶段，并约定“继续”表示写当前阶段的下一批：

阶段产出默认分批方式
1立项卡 + 企划案分 4 批
2全季资产库人物、道具、场景、特效
3分集剧本每次 3 集
4分集导演手册先资产图和时间轴，再每次 8 镜
5分集发布包按集生成

能写文件的工具（如 Claude Code、WorkBuddy）可以连续写完，并按固定目录存放：

片名/
  01-企划案.md
  02-资产库.md
  03-分集剧本.md
  04-导演手册/第01集.md
  05-发布包/第01集.md

只能粘贴使用的聊天工具，则按批次输出，每批开头标明进度，例如“第03集手册｜第2批／共N批｜镜1–8”。这个设计解决的是长内容一次性输出被截断的问题，但也意味着用户要主动管理批次和阶段。

阶段 1：企划案先把规则定死

以重生复仇模板为例，企划案包含 13 项，从核心创意、故事梗概、重生规则、人物关系，到逐集剧情、伏笔回收、视觉方案、复仇进度、地点空间、声音设计、制作与发布。

其中几项直接决定后面会不会返工：

  • 重生规则：重生时间点、前世结局、前世时间线、今生改变点、金手指规则与限制；
  • 逐集剧情与钩子：每集 2–3 句，加一句悬念，并标出付费卡点集；
  • 伏笔与回收：用表格记录埋设和回收位置；
  • 复仇进度：逐集目标、用了哪条前世记忆、对手损失；
  • 地点与空间：主要地点的布局和尺寸，避免同一场景在不同镜头里结构漂移。

模板还写了若干“踩过坑”的规则：前世和今生的时间线要算得清；主角改变过去后，先知能力要开始失灵；复仇之外要有新目标；仇人要分层，每个人的倒台都要有证据和因果；台词提到的人物必须在人物表里，重要配角要提前出场。

阶段 2：资产库是后面所有画面的基础

资产库按四类编号：人物 P01 起、道具 D01 起、场景 S01 起、特效 FX01 起。每张资产卡都给出可直接复制的提示词。

一致性靠几个具体机制维持：

  • 风格定调图：STYLE01 定今生正常色调，STYLE02 定前世低饱和冷调；后续前世和今生画面分别引用对应定调图。
  • 人物三视图：正面、侧面、背面同排等距，统一背景和光线。
  • 表情四态：选最能代表角色的四种表情，避免每集重新解释脸。
  • 服装卡与状态卡：标明使用集数；前世憔悴、今生意气、受伤状态分别建卡。
  • 一致性锚点：每人固定 3–4 个不变特征，例如疤痕位置、发饰，后面每集都要保持。
  • 场景的空景卡与机位卡：空景定空间结构，机位卡定构图和光效；同一地点的不同区域分别编号。

模板还要求资产命名可追踪，例如 人物_P01_今生通勤装_E01。这些编号会贯穿剧本、手册和发布包，后期查找和返工时不必靠文件名猜内容。

阶段 3：剧本要能直接指导镜头

分集剧本不是小说段落，而是分场和逐字对白。模板给出的结构包括：集名、时长、场景编号、出场人物、冷开场、场次、动作与画面、对白、内心独白、画外音、结尾钩子、本集进度、对白字数、是否卡点。

几条硬约束值得注意：

  • 每集 4–7 场，重生复仇题材对白约 300–500 字，时长变化时按比例调整；
  • 前 3 秒必须有动作或强台词；
  • 上集钩子要在第 1 场开头接住；
  • 内心独白和画外音计入总字数，开口对白单独统计；
  • 卡点集的结尾要停在“最大危机”或“真相揭开一半”的位置；
  • 后面的集不能比第 1 集写得短。

这些规则的目的，是让剧本不仅能读，还能直接转成有时长、有镜头、有声音的拍摄文档。

阶段 4：导演手册把文字变成可生成的镜头

导演手册只保留两部分：本集资产图和本集镜头，最后附连续性检查。它先给时间轴总表：镜号、镜头名、时间、时长、场景、生成方式、是否口型镜、首帧编号。总时长要验算，片尾卡和下集预告不计入正片。

每个镜头分三块：

A 段：分镜图提示词。 只定四件事：站位朝向、机位构图、起始姿势与道具状态、光线色调。外貌交给资产图，动作过程交给视频，表情只写一个词。冲突镜头只画动作之前或之后的稳定姿势，避免泼水、推搡、车祸的瞬间把图画崩。

B 段：视频提示词。 上方写参考图上传顺序，例如“Mixed 1＝P01 LOOK-B｜Mixed 2＝S03 空景卡”；正文用资产图锚定角色、场景和道具，再按时间段描述动作、台词、禁止项、约束、站位、运镜和音效。参考图规则要求模型只取角色形象，不取角度、构图和姿势；场景只取空间结构，不取机位；道具要注意正反面和多视图逻辑。

制作信息。 不粘贴给模型，只记录生成方式、特效合成、每句台词的精确起止秒数、音乐、转场和片名卡等后期内容。

这套 A/B 分段的价值在于职责分离：分镜图负责“这一帧长什么样”，视频提示词负责“这几秒怎么动”，资产图负责“这个人/场景/道具是什么”。三者混在一段提示词里，模型很容易在生成动作时改变人物外观。

阶段 5：发布包不只是封面

每集发布包包括：

  • 3:4 竖版和 4:3 横版封面提示词；
  • 3 秒片尾卡和 8–10 秒下集预告方案；
  • 3 个钩子标题、80–120 字简介、5–8 个话题标签、置顶评论；
  • 合规提示：标注 AI 生成内容，不用绝对化用语，不用真实人物肖像。

封面提示词沿用分镜图的五行结构，只把画幅改成对应比例，并给标题留出位置。片尾卡和预告接在正片之后，不占正片时间轴。

真正的差异在连续性检查

模板最实用的部分，是每集手册末尾的连续性清单。它检查的不是“画面好不好看”，而是那些会在第 20 集突然爆发的错误：

  • 时间轴首尾相接，总时长正确；
  • 编号和状态码都能在本集资产清单里找到；
  • 手册与剧本的本集进度一致；
  • 冷开场和后面某一镜的姿势、站位、台词对得上；
  • 正反打不越轴，动作方向不反；
  • 人物站位有过程，不能下一镜突然换位置；
  • 道具状态可追踪：何时出现、在谁手里、何时损坏；
  • 光线按世界方向定义，反打时不穿帮；
  • 白天戏里不说“今夜”；
  • 动作符合物理限制；
  • 前世和今生的状态卡、调色、服装、年龄感不能混；
  • 手机、合同、录音等证据在谁手里要能追踪；
  • 金额、股份等数字前后一致。

这份清单把“AI 生成的不稳定”拆成了可逐项检查的工程问题。它不能保证模型一定遵守，但能让检查有依据，而不是凭感觉重生成。

怎么用，以及它不做什么

在聊天工具里： 打开对应题材的 SKILL.md，复制全部内容，开新对话粘贴；模板回复“已就绪”后，发一句故事点子。一部剧用一个对话，一个对话只用一个模板，避免串设定。

在 Claude Code 里： 把题材文件夹复制到 ~/.claude/skills/，直接发故事点子。

在 WorkBuddy 里： 支持导入 Skill 的版本可以导入文件夹；不支持就按聊天工具的方式整段粘贴。

常用指令包括：一句故事点子、继续、第 N 集手册、第 N 集发布包、以及“改：女主改成冷面师姐”。最后一种只改相关部分，并检查前后是否矛盾。

它不负责的事情同样明确：

  • 不生成图片、视频或配音；
  • 不管理素材文件、版本和生成记录；
  • 不保证模型按提示词执行；
  • 不替代平台合规审核；
  • 不保证 21 个题材都经过同等测试。

README 的测试状态写得很具体：当前版本在 WorkBuddy 实测通过；玄幻修仙版经过实际使用测试；宫斗、宅斗、年代文、系统无限流、总裁甜宠、重生复仇、职场商战做过安装校验或阶段 1 试跑；其余题材尚未逐一实测。选题材时，这个差异比“21 个”这个数字更值得注意。

另外，{{Mixed N}} 是参考图引用写法，换到不同视频工具时需要改成对应格式。模板默认面向竖屏短剧，横屏、长片或完全不同的画风都需要改写默认值和风格前缀。

适合与不适合

适合：

  • 需要稳定量产竖屏漫剧的个人或小团队；
  • 已经有生图、视频、配音和剪辑工具，缺的是前期拆解和一致性管理；
  • 希望把“企划—资产—剧本—分镜—发布”固化成可复用文档；
  • 使用 Claude Code、WorkBuddy 等能读写文件、支持长上下文的 Agent。

需要谨慎：

  • 以为装上模板就能一键出片。它产出的是制作文档，不是成片；
  • 需要严格的版权、肖像和平台合规审查。模板只能提供提示，责任仍在使用者；
  • 需要复杂的多人协作、素材管理和版本控制。模板没有这些能力；
  • 题材属于悬疑刑侦、民俗怪谈等平台要求较高的类型。发布前应先确认规则。

上手前的检查清单

  • 选定一个题材模板，并确认它是否经过实际测试。
  • 用一句点子生成立项卡，先检查默认集数、时长、画幅和风格是否符合目标平台。
  • 确认人物、公司、城市均为原创，没有沿用真实品牌、真实人物或已有作品设定。
  • 资产库的编号、状态码和一致性锚点已经建立，并能被后续剧本引用。
  • 抽一集检查剧本字数、前 3 秒钩子、结尾钩子和卡点是否符合模板规则。
  • 抽一镜检查 A 段分镜是否只写站位、构图、姿势和光线，B 段是否正确引用资产图。
  • 按连续性清单逐项检查时间轴、越轴、道具、光线、证据和数字。
  • 确认视频工具支持 {{Mixed N}} 的等价写法，并实际跑通一条镜头。
  • 发布前标注 AI 生成内容，核对平台规则、肖像授权和音乐/字体许可。
