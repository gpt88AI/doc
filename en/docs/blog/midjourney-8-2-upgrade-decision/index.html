Should You Upgrade to Midjourney V8.2? Run This 8-Cell Acceptance Board First

模型对比2026-07-2914 min readMidjourney V8.2Midjourney V8.1Workflow MigrationImage AcceptancePersonalization

Midjourney V8.2 已在 2026 年 7 月 24 日成为默认版本。对全新的探索项目，可以直接从 V8.2 起步；对已经稳定交付的海报、商品图、角色系列或品牌视觉，先不要因为一张更漂亮的样图就批量迁移。最稳妥的第一步，是从你自己的已验收工作里抽出 8 条提示词，固定比例、Raw、stylize、可用的 seed、Personalization 配置和 SD/HD 模式，再逐条记录 V8.1 与 V8.2 的可交付差异。

这不是一份已经跑完的 Midjourney 实测。本文没有访问你的账号、没有生成这 8 组图片，也没有观察到重试次数，因此下方所有证据格都保留为"未运行/未知"。它提供的是一套可以真正执行的迁移验收包：每条最多重试两次，最后只能进入"保留 V8.2""只复测一个变量""回退旧版本"或"未知/未运行"四种状态。

先用 30 秒判断：你现在需要升级，还是需要验收

你的处境现在怎么做为什么
新项目，没有旧版本基线先用默认 V8.2 做第一版，同时保存完整参数没有旧交付需要保护，但仍要留下可复现记录
旧项目正在稳定交付先跑本文的 8 条提示词，不要直接替换默认版本美学变化可能是改进，也可能破坏客户已经接受的风格
依赖 Personalization新旧 profile 都测，不能只测一个Midjourney 官方特别建议在 V8.2 上同时尝试新旧 Personalization profile
依赖 Omni Reference先停下，按 V7 路径核对当前官方文档把 Omni Reference 放在 V7 路径，不能把结果标成原生 V8.2
正在比较 GPT Image 2 与 Midjourney把"版本迁移"和"跨模型选型"拆成两次测试两个问题的控制项、输入能力和失败成本不同，混在一起不会得到可信赢家

如果一条任务没有历史基线，V8.2 的输出只能告诉你"这张能不能用"，不能告诉你"升级有没有变好"。如果有历史基线，却在比较时顺手改了提示词、比例、profile 或执行模式，结果也只能标成"需要复测"，不能算 V8.2 的胜负。

官方更新说明了方向，但没有替你完成迁移决定

Midjourney 的发布说明把 V8.2 的重点概括为美学、图像质量和 Personalization，并鼓励用户尝试新旧 Personalization profile。官方版本文档同时说明：V8.2 自 2026 年 7 月 24 日起成为默认版本。

这些是当前产品状态与官方目标，不是你项目的验收结果。第三方页面常把"更有细节""更贴合提示词"直接写成总评，但同一个变化可能让商品材质更可信，也可能让原本依赖意外感的超现实画面变得过于直白。社区中也同时存在"细节更丰富"和"少了意外感"的个人反馈；这能证明迁移疑问真实存在，却不能证明哪种体验更普遍。

因此，判断单位不该是一张首页样图，而应该是一项已经定义了失败条件的生产任务。

开始前先冻结 6 类控制项

把旧版本已接受的输出放在旁边，然后为每条提示词记录下面这些字段。没有记录，就不要开始打分。

  1. 任务关键约束：主体数量、必需物体、不能改变的文字、姿态、镜头和构图。
  2. 画幅与风格控制：宽高比、Raw、stylize、style reference 或 moodboard。
  3. 随机控制：保留可用的 seed；如果无法精确复现，就写"最接近的可复现控制"。
  4. Personalization 配对：如果工作流使用 Personalization，分别记录旧 profile 与新 profile。
  5. 执行模式：明确 SD 或 HD，以及界面上能看到的其他模式，不能把不同模式混成一个版本结论。
  6. 交付检查方式：先规定最终尺寸和检查缩放比例，例如"广告成品 100% 查看文字与手部，25% 查看视觉层级"。

官方兼容表把 V8.1 与 V8.2 的 seed 描述为大约 99% 相同，而不是像素级完全一致。相同 seed 有助于减少随机差异，但不能把两张图当作只改变了一个像素级变量的科学对照。当前兼容表还把 Quality 与 Draft Mode 标为不支持；如果界面或旧提示词里出现这些控制项，应记录实际路径，不要把一次尝试写成"V8.2 高质量模式已验证"。

8 条提示词迁移验收包

先从你过去 30 天的真实工作中选 8 条，而不是从网上挑 8 条容易出好图的展示 prompt。下面的"提示词槽位"给出选取逻辑；请把方括号替换成你自己的完整提示词，并附上旧版已接受输出。第一次打开这张表时，所有状态都应该是"未运行/未知"。

#从真实工作中复制的提示词槽位本行必须守住的约束V8.1/旧版证据V8.2 证据已用重试当前状态
1[已交付的单人主视觉提示词]面部、服装关键件、镜头距离、主光方向未粘贴/未知未运行/未知0/2未运行/未知
2[带标签或包装的商品提示词]商品轮廓、标签位置、颜色、材质、配件数量未粘贴/未知未运行/未知0/2未运行/未知
3[多人或多主体叙事场景]人数、相对位置、动作关系、背景层级未粘贴/未知未运行/未知0/2未运行/未知
4[手与工具/器皿发生接触的提示词]手指数、接触点、握持方向、工具形状未粘贴/未知未运行/未知0/2未运行/未知

6[刻意追求隐喻或超现实意外感的提示词]核心隐喻仍可读，同时不能退化成字面拼贴未粘贴/未知未运行/未知0/2未运行/未知

8[依赖 Personalization 的高频提示词]旧 profile 与新 profile 分开记录，目标审美不漂移未粘贴/未知未运行/未知0/2未运行/未知

这 8 行不是八种固定行业，而是八个风险槽位。你的工作没有商品包装，却高度依赖建筑透视，就把第 2 行换成最难的建筑任务；你的工作完全不用 Personalization，就把第 8 行换成一个高频交付任务，并在配置里明确写"不使用 Personalization"。不要为了填满模板而测试不相关能力。

每一行只做四项验收

验收项通过时能看到什么失败时怎么记
主体与任务约束保留必需主体、数量、动作、文字或商品特征都在，且没有新增会导致拒收的内容写出丢失、替换或新增的具体对象，不写"感觉不对"
交付缩放下的细节连贯性在最终交付尺寸查看时，手部、边缘、材质、透视和接触点仍然合理标明缩放比例和具体破损位置
提示词遵循与构图画面层级、镜头、空间关系和指令中的硬约束都能被识别区分"审美偏好不同"和"明确指令未完成"
Personalization 契合度使用 profile 时，输出仍符合团队已经定义的色彩、质感和构图偏好写清测试的是旧 profile 还是新 profile；不用则记"不适用"

审美偏好与生产失败不能混为一谈。"我更喜欢 V8.1 的偶然感"是审美判断；"三人场景少了一个人"是提示词遵循失败；"包装文字改变"是任务关键约束失败；"100% 查看时玻璃边缘断裂"是细节连贯性失败。把它们拆开，团队才知道是接受新风格、改一个变量，还是直接回退。

怎么跑：一行最多两次重试

对每一行按这个顺序执行：

  1. 在 V8.1 或当前稳定版本上打开已接受输出，补齐当时的完整提示词和可见参数。找不到参数时，不要猜，写"基线不完整"。
  2. 在 V8.2 上保持提示词、比例、Raw、stylize、可用 seed、profile 与 SD/HD 模式一致。版本以外有任何变化，都写入记录。
  3. 按交付尺寸检查四项验收，不要先从四宫格里挑最漂亮的一张再补理由。
  4. 首次失败时，判断是否存在一个可隔离变量。只有能明确命名这个变量，才允许第一次重试。
  5. 第二次重试后仍无法通过，就停止这一行。不要用无限 reroll 把迁移成本藏起来。

两次是每行的重试上限，不是必须花完的额度。第一次已经通过就停止；一次重试只是因为测试时误开了不同 profile，也应把它记成"测试配置修正"，而不是把失败从记录里删掉。

保留、复测还是回退：用硬门槛收尾

保留 V8.2

只有同时满足以下条件，才把这套工作流标成"保留 V8.2"：

  • 8 行全部保住任务关键约束；
  • 没有关键行在细节连贯性或提示词遵循上失败；
  • 使用 Personalization 时，新版保持或改善了团队想要的审美；
  • 没有任何一行超过两次重试预算。

这不是"V8.2 普遍更强"的结论，只说明它通过了这一组工作负载的迁移门槛。

只复测一个变量

以下情况进入"只复测一个变量"：

  • 证据缺失，无法判断；
  • 测试时不小心改变了一个控制项；
  • 一条非关键行失败，并且存在一个可解释、可隔离的变量。

下一轮只能改一个已记录变量，例如只切换旧/新 Personalization profile，或只恢复原始 stylize。不要同时改 prompt、比例和 profile，否则仍然无法知道原因。

回退旧版本

出现任一情况，就把当前生产工作流标成"回退"：

  • 一条关键任务在两次重试后仍丢失必需内容或结构连贯性；
  • 多行耗尽两次重试预算；
  • 新默认版本破坏了工作流依赖的功能路径。

回退是对当前项目的风险控制，不是给 V8.2 下永久结论。新项目、不同题材或官方兼容性变化后，可以重新开一张验收表。

未运行/未知

空白证据、无法访问的账号输出、没有保存的旧参数，都只能记为"未知/未运行"。未知不计入成功，也不计入失败，更不能为了让 8 行看起来完整而填成通过。

GPT Image 2 什么时候才应该进入这张表

如果你的问题原本是"Midjourney 8.2 vs GPT Image 2 谁更好"，先确认你究竟在做哪种决定：

  • 迁移已有 Midjourney 项目：先完成本文的 V8.1/旧版本对 V8.2 验收。GPT Image 2 不属于这个版本迁移问题。
  • 为一个新任务选生成路线：另开跨模型测试，给两条路线同一业务目标、同一输入素材、同一交付尺寸、同一拒收条件和可比的重试预算。
  • 需要编辑现有图片或延续特定输入资产：先核对两条路线实际支持的输入、编辑和参考能力，再设计对照；不能假设同名"图像生成"意味着合同相同。

本文没有同输入、同验收标准下的 Midjourney V8.2 与 GPT Image 2 输出，所以不会宣布通用赢家。尤其不要把一个模型的四宫格最佳图和另一个模型的单次结果直接比较，也不要把无限 reroll 后的最佳样本当作一次通过。

当前 GPT88 配置也不提供 Midjourney V8.2 执行路线。要跑上述验收，应在 Midjourney 官方界面完成，不要把第三方工作台或本文的说明误认为 GPT88 能生成 Midjourney 输出。如果你只是想在不带敏感素材的情况下快速摸清免费生图工具的边界，可继续看免费 AI 图片生成器无需注册；那是另一项任务，不替代 Midjourney 迁移验收。

常见问题

Midjourney V8.2 现在是默认版本吗？

是。Midjourney 当前版本文档写明，V8.2 于 2026 年 7 月 24 日作为默认版本发布。默认不等于你的旧项目已经通过迁移，生产项目仍应保留旧版本基线并做验收。

相同 seed 能保证 V8.1 与 V8.2 完全一致吗？

不能。当前官方兼容表把 V8.1 与 V8.2 的 seed 描述为大约 99% 相同，而不是像素级一致。seed 是减少随机差异的控制项，不是"只改变版本"的绝对证明。

可以用 Quality 或 Draft Mode 验证 V8.2 吗？

按 2026 年 7 月 29 日检查到的官方兼容表，V8.1 与 V8.2 列把 Quality 和 Draft Mode 标为不支持。界面和文档可能变化，执行前应重新核对；当前不能把带这些参数的一次尝试宣传成已验证的 V8.2 模式。

Omni Reference 是 V8.2 的原生路径吗？

不是。当前官方 Omni Reference 文档把它放在 V7 路径。需要该能力时，应按 V7 工作流记录，不能把输出标成 V8.2 原生结果。

八行里有一行没跑，可以先决定升级吗？

不能把整套工作流标成已通过。你可以缩小结论，例如"目前只验证了商品静物的两条任务"，但未运行行仍然是未知。若未运行的是关键交付类型，应维持旧基线，等证据补齐再决定。

这张表能证明 V8.2 比 GPT Image 2 更好吗？

不能。它只负责 Midjourney 版本迁移。跨模型结论需要同一业务目标、相同输入和拒收条件下的可复核输出；本文没有执行该测试，也没有保留可供审核的结果文件。

最后的执行顺序

今天只做三件事：先复制 8 条真实工作提示词，再冻结 6 类控制项，最后把每行的失败条件写在生成按钮之前。测试结束后，按门槛进入保留、单变量复测、回退或未知。这样得到的不是一张"哪张更好看"的投票，而是一份团队能复查、能停止、也能安全撤回的迁移决定。
