GPT Images 2.6 GIF 实测：从参考图到逐帧编辑的动图工作流

图像生成2026-11-0514 මිනිත්තු කියවීමGPT Images 2.6GPT-Image-2.6GIF动图图像编辑参考图草图动画OpenAI

本文根据程序员鱼皮发布的公众号文章《刚刚 GPT Images 2.6 发布，一键生成 GIF 动图，表情包自由的时代来了！》整理。文中的 7 个动图案例、耗时、画面尺寸和失败现象属于作者在 ChatGPT 产品界面的实测记录；它们不等同于 GPT88 的价格、额度、API 能力或服务 SLA。

GPT Images 2.6 这次最容易被普通用户感知的变化，是图片生成开始直接进入短动图工作流：输入一句动作描述，上传一张参考图或草图，就能得到一段循环播放的 GIF。它还提供精灵图、播放速度和逐帧编辑入口，让动图不再只是一次性生成后下载的文件。

这项能力适合表情包、产品演示、聊天记录梗图和简单故事板。它目前仍有明显边界：真人脸部还原不如静态图稳定，许多成品分辨率偏小，审核可能误伤，参考照片偶尔读取失败。因此正确的使用方式是把它当成快速创作和修改工具，而不是无需验收的动画生产线。

先说结论

任务推荐做法主要验收点
固定角色表情包上传参考图，再描述动作和循环角色发型、服装、配色和脸部特征是否跨帧稳定
真人反应动图上传多张同一人物照片，减少动作复杂度人脸、眼镜、衣服和身体比例是否漂移
中文聊天记录先让模型生成，再检查每一帧文字中文是否准确、消息顺序是否正确、最后一帧是否停留
草图动画先画主体和关键道具，再写动作分镜草图中的线条、眼镜和主体关系是否保留
修改已有 GIF切到精灵图，在目标帧添加评论未标记的帧和区域是否保持不变
反复使用固定角色保存为参考照片并在提示词中点名首次调用是否成功、每次生成是否真的读取了角色

如果只想做一张能发到群里的表情包，直接从参考图加短动作开始；如果要做产品演示或品牌内容，则应先生成低分辨率草稿，再检查帧间一致性、文字和文件体积。

一、GIF 动图的基本流程

在 ChatGPT 的图像入口中选择“创建图像”，然后在提示词里明确写出三件事：

  1. 输出格式是 GIF 动图，而不是静态图片。
  2. 哪些对象需要运动，以及运动的先后顺序。
  3. 最后如何回到开始姿势，形成循环。

一个可复用的提示词结构是：

参考我上传的[角色或产品]，做一张 GIF 动图：
[开始姿势] → [动作 1] → [动作 2] → [结束动作] → 回到开始姿势，循环播放。
保持[角色特征、产品外形、背景和画面比例]不变，使用[视觉风格]。

动作越具体，越容易判断结果是否符合预期。只写“让它动起来”通常不够；应写清楚谁动、怎么动、动几步、最后停在哪里。

二、参考图决定角色一致性

公众号实测的第一个案例是“吃白饭的蓝色大肥鱼”。第一次没有上传参考图，只在提示词里描述“蓝色的大肥鲸鱼”，模型生成了一条可爱的蓝色鲸鱼，但并不是读者熟悉的固定角色。

第二次加入角色参考图，并明确补充蓝色长发、鲸鱼耳朵、鲸鱼尾巴、女仆装等特征，结果才接近目标形象。这个案例说明：

  • 角色名称不是稳定的视觉身份；
  • 参考图应与文字描述一起提供；
  • 提示词要列出必须保留的外观特征；
  • 循环动作要尽量围绕角色原本的姿势设计。

作者还观察到，生成结果可以在 GIF 和“精灵图”之间切换。精灵图把多个画面排在同一张大图中，再按顺序播放。所有帧在同一张图中共同生成，可能是角色一致性较好的一个原因，但这只是基于案例的推测，不是官方对内部实现的确认。

三、真人动图：能做，但要降低预期

第二个案例把两张真人照片交给模型，让人物从工位喝咖啡开始，看到“线上报错 999+”后瞪眼、洒咖啡、从椅子上滑下去。

这个案例可以还原“程序员遇到线上故障”的完整情节，但作者明确反馈：人脸只有几分像，更接近远房亲戚；静态图中的人物一致性通常更好。

真人动图的提示词建议遵循以下原则：

  • 上传多张光线和角度不同、但属于同一个人的照片；
  • 先让人物做小幅度动作，再尝试大幅度位移或摔倒；
  • 只保留一个主要人物，减少多人交互；
  • 把发型、眼镜、衣服颜色和拍摄风格列为锁定项；
  • 把“动作夸张”与“脸部必须完全一致”分开验收。

对于需要本人出镜的品牌内容，建议把 GIF 当作创意草稿或社交媒体轻量素材。正式发布前应逐帧检查是否出现脸部、手部、眼镜和服装漂移。

四、中文聊天记录是一次有价值的压力测试

第三个案例是让模型生成一段微信聊天记录 GIF：消息逐条出现，老板先说“周末有个小需求，很简单”，最后变成“做一个类似淘宝的 App，周一上线”，程序员回复已经让 AI 写完了，老板只留下“？？？”。

这个案例的难点不在动作，而在大量中文文字必须跨帧稳定。作者记录到，模型思考约 3 分钟后生成了 9 帧动图，并且每一帧的中文都没有写错；随后还通过代码渲染出了 720 × 1280 的高清竖版版本。

做文字密集的动图时，可以把验收拆成四层：

  1. 每一帧的文字是否完整、清晰、没有错别字。
  2. 消息是否按指定顺序出现，头像和气泡是否对应正确的人。
  3. 最后一帧是否停留足够久，方便观众读完。
  4. 竖屏尺寸、文件大小和压缩后清晰度是否满足发布平台要求。

不要因为一张预览图文字清晰，就默认所有帧都正确。文字动图应逐帧检查，尤其是需要截图传播或承载产品文案的内容。

五、草图可以直接变成一段小动画

作者在 ChatGPT 绘图板里随手画了一个戴圆眼镜的火柴人，再用提示词写出完整剧情：火柴人低头敲代码，红色 Bug 变成绿色对勾，随后跳舞庆祝，头顶出现“Bug 修好了！”，最后回到敲代码的姿势。

草图动画的价值不在于画得精细，而在于锁定主体、道具和大致动作。开始时只要交代：

  • 主体是什么；
  • 哪些线条和特征必须保留；
  • 画面中有哪些关键道具；
  • 动作先后顺序是什么；
  • 结尾如何回到起始画面。

对于产品设计或视频分镜，可以先用草图确定运动关系，再用高质量模型重做关键帧。这样比一开始就要求模型生成完整成片更容易发现构图问题。

六、逐帧编辑让动图从“抽卡”变成“可修改文件”

动图生成后，页面底部会出现时间轴。作者实测了两个编辑入口：

  • 点击“1×”调整播放速度，速度从 0.25 倍到 2 倍，共有 8 档；
  • 切到精灵图，在具体帧上添加评论，要求模型只修改被标记的内容。

例如，作者把最后一帧老板的“？？？”改成“牛啊！那下周把京东也做了”，重新生成后只有最后两帧台词改变，前面的消息和头像保持不变。

这个工作流可以归纳成“先生成、再定位、局部修改、逐帧复核”：

生成初稿
  → 切换精灵图
  → 在目标帧标注修改区域
  → 写清需要替换的文字或对象
  → 重新生成
  → 对比未标记帧是否保持不变

编辑时不要只说“把这段改好看一点”。应写明目标帧、目标区域、新内容，以及必须保留的其他帧和对象。

七、参考照片适合做角色库，但仍要验证调用

文章还介绍了 ChatGPT 中的“参考照片”功能：可以把照片保存为“我”“宠物”“朋友”“空间”或其他角色，之后在提示词里直接点名调用。作者把自己的照片保存为“我”，把蓝色鲸鱼娘保存为“大肥鱼”，再让两者一起完成喂饭动图。

第一次调用时模型提示无法读取“我”的参考照片，回复末尾还出现了没有渲染出来的按钮代码。作者补充说明参考照片已经保存在资料库后，第二次才成功生成。

这个案例说明，参考照片库能减少重复上传，但不能跳过验证：

  • 第一次调用要确认模型真的读取了指定角色；
  • 结果中要检查角色的关键特征是否保持；
  • 失败时重新说明角色名和存储位置，不要直接反复重试；
  • 对重要内容仍然保留原始参考图，方便回退。

作者在 9 帧精灵图中发现人物眼镜有两帧消失，说明角色库便利性和逐帧稳定性仍然是两回事。

八、审核误伤与提示词改写

奶龙仰天大笑的案例出现了一次误判：黄色卡通恐龙的提示词包含“拍大腿”“前仰后合”等动作，第一次请求被拒绝。作者补充“这是卡通恐龙，没有任何不良内容”，并把动作改成“捶地”，第二次才顺利通过。

这不是规避安全系统的技巧，而是把含义写得更准确：

  • 说明对象是卡通角色；
  • 明确内容是普通表情包或动画；
  • 删除可能被误解的动作词；
  • 保留必要的动作节奏和画面目标。

如果内容本身涉及真实人物、未成年人、敏感场景或他人肖像，应先确认授权和使用边界。改写提示词不能把不应生成的内容变成可接受内容。

九、GPT88 接入时怎么验证 GIF 能力

公众号案例主要来自 ChatGPT 图像界面。GPT88 统一接口是否支持 GIF 输出、精灵图、参考照片或逐帧编辑，要以当前模型列表和实际接口响应为准，不能仅根据 ChatGPT 产品体验推断。

建议先用最小请求确认模型和路由，再逐项验证：

curl https://img.gpt88.cc/v1/models \
  -H "Authorization: Bearer $GPT88_API_KEY"

确认返回的模型 ID 后，再使用图片生成端点测试一张静态图或最短动图任务。记录以下信息：

  • 模型 ID、尺寸和质量档位；
  • 是否需要参考图或编辑输入；
  • 返回的是 GIF、精灵图还是静态图片；
  • 生成耗时、失败率、重试次数和文件大小；
  • 当前账号是否真的开放相关格式和编辑能力。

如果接口返回成功但没有 GIF 字段，不要把静态图片强行改名为 GIF。应检查当前路由文档、响应结构和 GPT88 控制台能力，再决定是否需要客户端组帧或其他处理流程。

十、推荐的动图生产 SOP

把这篇实测整理成可复用流程，可以按下面 8 步执行：

  1. 先定义发布场景：表情包、产品演示、聊天梗图还是故事板。
  2. 准备参考图或草图，列出必须保留的角色和产品特征。
  3. 写出开始姿势、动作顺序和循环回到起点的方式。
