Optional analytics

If you allow it, we analyze only the documentation page, campaign, and Agent entry click to improve the docs and setup flow. The optional analytics event payload contains no email, prompts, API keys, tokens, account, device, or browser identifiers. Basic request metadata is used only for security and rate limiting, not analytics profiling.

DeepSeek 四天三连击：模型升级、开放搜索与 DeepInfer 开源

AI行业观察2026-10-2212 நிமிட வாசிப்புDeepSeek大语言模型搜索推理框架开源AI基础设施

本文根据公众号作者快刀青衣 2026 年 10 月 22 日发布的文章整理。文中性能榜单、价格和吞吐数据均为原文转述，本文未独立复测；关于行业影响的部分属于基于原文信息的分析。

DeepSeek 在四天内连续发布了三项进展：10 月 17 日更新 V4.1 Flash 1017 权重并开放自研搜索 API，10 月 20 日开源内部推理框架 DeepInfer。把它们放在一起看，变化不只发生在模型本身，还覆盖了模型怎样获取信息、怎样被部署和运行。

可以用三层来理解这组动作：模型升级提升“能做什么”，搜索 API 试图改善“依据什么回答”，推理框架则影响“以什么成本把能力交付出来”。

一、V4.1 Flash 1017：只改权重也可能带来明显变化

作者称，DeepSeek 将 1017 定义为一次 minor update：模型结构、分词器和提示词格式没有改变，主要变化在权重。版本号听起来不大，但文章转述的测试成绩和实际任务案例显示，体验差异可能相当明显。

编程成绩与实际任务

文章援引 DeepSWE 软件工程榜单称，1017 得分为 77.0，高于文中列举的 Claude Opus 5（74.0）和 GPT-5.6 Sol（73.0）。作者同时特别提醒，这些对照并非竞争对手各自的旗舰模型。在 Code Arena 的 WebDev 赛道，文章称 1017 获得 1670 分，是当时成绩最高的开源模型，和 GPT-6 Sol 相差十余分。

这些数字说明的是特定评测、版本和时间点上的结果，不能直接推导出所有编程任务里 1017 都更强。榜单任务的覆盖范围、工具配置、提示词、推理预算和模型版本都会影响比较。对实际使用者来说，更稳妥的做法是用自己常见的代码库任务做对照，检查正确率、可运行性、修改范围、耗时与返工量。

文章还转述了两个生成任务的成本案例：生成“鹈鹕骑自行车”动画，1017 用时 172 秒、花费约 0.17 元；文章比较的 V4-Pro 用时 240 秒、约 0.31 元，Claude Opus 5.5 用时 519 秒、约 8.5 元。另一个案例是根据特斯拉飞行发布会片段生成动态 3D 网页，作者称 1017 最终完成了从地面加速到空中悬停等关键画面，花费约 4 元。

这类单次任务适合观察“速度、价格、交付效果”的可能组合，但不是标准化基准。输入材料、重试次数、模型调用链和验收标准若不同，成本与质量就不能简单横向比较。

自反馈强化学习与“许愿式编程”

按文章对官方说明的转述，此次训练采用了基于自反馈的强化学习：让模型生成题目、对结果打分，再用评分信号改进。它的潜在价值是减少训练过程对人工反馈的单点依赖，让生成、评价和迭代可以持续运行。这里的“自反馈”并不意味着模型能自动保证判断正确，评价信号本身的质量仍会决定训练效果。

作者也提到，1017 加强了从零搭建完整项目的能力，并把自然语言提出目标、由模型生成完整项目称作“许愿式编程”。文中举出的演示包括故宫 3D 建模和网页赛车游戏；一位实测者据称用 Claude Code 搭建太和殿 3D 模型，约 23 分钟完成，成本约 1.4 元。此类展示说明模型可能把多步骤开发压缩为更短的交互，但生产使用仍要检查代码质量、素材与版权、浏览器兼容性、边界条件和后续可维护性。

对 API 用户而言，如果能力提升而定价保持不变，实际单位能力的成本可能下降。作者将其概括为用户“免费享受升级”。这成立与否仍需结合真实任务的成功率、调用量和重试成本判断，不能只看标价。

二、搜索 API：把信息质量作为产品能力的一部分

与模型更新同日，DeepSeek 开放了自研搜索 API。文章特别关注公告中关于识别和过滤 SEO 作弊、GEO 操纵与低质量 AIGC 内容的表述。其核心问题是：搜索系统不仅要找到网页，还要判断哪些网页值得进入模型的上下文。

从搜索结果污染到回答污染

SEO 的目标通常是提高页面在传统搜索结果中的可见度。文章把 GEO（生成式引擎优化）描述为面向生成式系统争取推荐或引用的做法。正当的内容优化可以帮助内容被发现，但批量制造只为影响模型而写的内容，也可能让低质量或带有商业偏向的信息进入回答链条。

传统搜索把候选页面展示给用户，用户还能查看来源、比较多个结果。由检索系统挑出的内容若直接进入模型上下文，用户看到的则可能是一段连贯、确定的综合回答，较难判断其中哪些结论来自可靠来源、哪些受检索材料影响。因此，搜索质量会直接影响模型回答的依据，而不只是搜索页的排序。

文章用数码产品推荐举例：如果回答的大部分选项都可信，夹杂其中的低知名度或低质量推荐更容易被接受。若将同样机制用于食品、健康等领域，错误或被操纵信息的后果会更大。这里的风险不在于所有 GEO 内容都是恶意，而在于用户通常看不到内容筛选和排序的全过程。

过滤机制能解决什么、还不能证明什么

文章认为，DeepSeek 把 SEO 作弊、GEO 操纵和低质 AIGC 明确列为过滤对象，说明搜索质量控制开始进入产品设计。但公告表述只能说明供应方设定了这样的目标，不能单独证明过滤覆盖率、误判率或长期抗操纵效果。

评估搜索 API 时，仍应观察几类问题：权威来源是否更容易被召回；新近信息是否能正确标注时间；不同观点是否被保留；正常但表达相似的内容是否被误伤；结果是否提供可追溯的来源。对于模型应用开发者而言，检索结果的来源、时间和引用呈现应进入评测集，而不是只评最终回答是否流畅。

三、DeepInfer：开源推理系统，分享模型之外的工程经验

10 月 20 日，DeepSeek 宣布开源内部推理框架 DeepInfer。推理是模型接到请求后生成结果的过程。推理框架负责请求调度、显卡任务分配和多卡协同等运行时工作，因此会影响吞吐、延迟和算力利用率。

可以把模型比作厨师的手艺，把推理系统比作厨房布局：同样的模型，在调度合理、设备利用率高的系统中，单位时间可以服务更多请求；系统效率低，则可能浪费硬件资源。框架不会自动让模型“更聪明”，但会影响模型能力能否以可接受的成本稳定提供。

原文转述的吞吐与收入数据

作者援引 DeepSeek 技术报告称，基于 DeepInfer 的单一集群每天处理约 155 万亿 Token，折算为每卡每小时约 38 美元收入。文章将其视作算力变现效率的重要指标，并称不少云上算力出租机构的相应指标约为 10 美元左右。

这组数据需要结合报告的具体口径理解：集群规模、卡型、利用率、收入计算方式、服务质量和成本是否计入，都会改变比较结果。文章将 DeepInfer 称为“印钞机图纸”，强调的是推理工程的经济价值；不能仅凭公开框架代码就复现同样的商业指标。

开源版的价值和边界

在框架开源之前，开发者可以取得模型权重并自行部署，却仍要自行解决推理优化和集群工程问题。现在，公开推理框架有机会缩短团队摸索调度、执行和服务优化路径的时间，也让云厂商更容易围绕开源模型构建服务。

不过，按文章说明，开源的是可以独立部署的版本；DeepSeek 在线服务中与其集群深度绑定的调度系统，例如存储管理和负载均衡，并不都包含在内。因此，“能运行”不等于“运行成本与官方服务相同”，更不意味着简单复制即可达到每卡每小时 38 美元。硬件、负载形态、网络、存储、运维能力和服务质量仍然是关键变量。

文章称 DeepInfer 使用 Apache 2.0 许可证，允许广泛使用和商业化。实际采用时，团队仍应以仓库中的许可证文件和第三方依赖许可为准，并核对具体版本及相关权利义务。

四、三项动作放在一起看

这三件事分别作用于 AI 服务链的不同层面：

动作直接作用对使用者的潜在影响需要验证的部分
V4.1 Flash 1017 权重更新模型能力与任务表现同等预算下完成更多工作，或降低复杂任务成本自有任务成功率、耗时、重试与质量
自研搜索 API外部信息召回与筛选回答依据可能更及时、更能抵御低质内容来源覆盖、时效、误召回、引用可追溯性
DeepInfer 开源推理运行与部署降低自建服务的工程起点，分享优化经验实际硬件成本、稳定性、吞吐和运维复杂度

从产业角度看，这种组合说明竞争焦点不只在参数规模和单项榜单成绩。模型质量、检索质量和推理效率共同决定一项 AI 服务是否实用、可信且可负担。开源权重解决“拿到模型”的问题，开源推理系统进一步公开部分“如何运行模型”的经验，而在线服务所需的完整工程体系仍有额外门槛。

五、开发者和团队可以怎样跟进

如果正在使用模型 API，可以用固定任务集比较新旧版本，记录输入、模型版本、工具配置、成功率、延迟、费用和人工返工量。对编码任务，应检查改动是否符合仓库约束、测试是否通过、是否引入不必要的重构；对多媒体或网页生成任务，应增加浏览器实测和交付物验收。

如果在应用中接入搜索，应把检索质量与答案质量分开评测。保存来源、发布时间和检索片段，抽查答案中的关键事实是否能回到原始出处，并为高风险主题设置更严格的来源要求。

如果考虑自建推理服务，先基于目标负载做小规模测算：并发、上下文长度、输出长度、峰值比例、目标延迟、硬件价格与运维成本都应纳入。开源代码能减少重复探索，但部署结果仍取决于自己的软硬件环境。
