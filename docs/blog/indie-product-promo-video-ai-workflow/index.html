独立开发者 AI 产品宣传片工作流：从真实 UI 到 15 秒样片

AI视频制作2026-11-07约 16 分钟AI视频产品宣传片独立开发ClaudeCodexSeedanceRemotion

独立开发者把产品做出来后，常常还要解决另一个问题：怎样让第一次看到产品的人，在几十秒内理解它解决什么问题、真实界面是什么样、结果是否可信。把几张截图套进设备模型、配上标题和转场，虽然能快速导出视频，却未必能把产品讲明白。

本文整理自 BaiFu 的 X 长文《连做 4 条百万曝光产品宣传片后，我想给独立开发者留下一份教程》，原帖见 BaiFu 的分享。原文报告了 Auday 宣传片的曝光表现和作者对工具的选择；这些属于作者自述与个人判断，不是独立验证的效果承诺，也不代表当前模型版本或价格仍相同。

先决定这支片子要完成什么

原文反复强调，产品宣传片不是功能清单，也不是单纯展示视觉效果的 AI 短片。开工前先确定三件事：谁会看、准备发布在哪里、希望观众记住哪一个价值。回答不清，就先不要让 Agent 读取整个代码仓库后自动罗列功能。

一条宣传片通常只需要一个主要任务：

片型面向观众主要目标
产品首发片从未听说过产品的潜在用户迅速说明痛点、产品怎么用，以及结果为何可信
功能介绍片已有用户或社区受众用简单、自然的方式演示一项核心功能
品牌形象片希望记住品牌气质的人不讲复杂操作，用鲜明视觉符号留下印象

作者以自己的 Auday 项目为例，称其功能不少，但首发片不可能逐一介绍。更有效的组织方式是选择一个具体问题，让一个真实使用场景把功能和结果连起来。原文称其团队做出了多条获得大量曝光的宣传片，这应理解为作者的项目经历，而不是复用同一流程就能获得的结果保证。

把工具按职责拆开

作者当时的工作台把产品取材、镜头编排、视频生成、配音和最终合成分给不同工具：

  • Codex 读取项目代码、运行产品、导出真实 UI、准备公开演示数据并执行脚本。
  • Claude 负责叙事、构图审美、镜头衔接和代码动画编排。原文对 Claude Opus 5.5 的评价是作者个人比较体验，不宜泛化成所有任务或模型的排名。
  • Seedance 负责补充生活场景等实景底片，而不是生成带有真实软件文字和图标的界面。
  • MiniMax TTS 用于试听和生成旁白。
  • Remotion、FFmpeg、Python 用于合成、时间线控制、转场、音画同步和导出。

这套分工的重点是把“产品事实”与“画面表现”分开：真实功能和界面从运行中的产品取得，生成模型补足环境和氛围，代码则负责可预测的布局和节奏。工具名称可以替换，职责边界更值得保留。

制作素材也可以先分三类：项目里已有的真实界面与品牌资产、用代码完成的文字和动画、确实需要生成的生活实景。只有第三类才需要调用视频生成模型，这能避免为了每个镜头都生成视频而增加成本和不确定性。

首发片：按观众的疑问顺序给证据

面对陌生观众，开场应该尽快交代“这和我有什么关系”。可以先提出一个具体痛点，再让真实设备或产品界面立刻出现并完成一次操作。之后沿着一个使用案例展开：观众先看到问题，再看到产品如何操作，最后看到可验证的结果。

原文指出，逐个介绍功能容易变成“录音、搜索、问答、总结……”的列表，观众看过后仍不知道哪个功能真正解决了问题。作者在项目片中把多个能力放进一个具体使用情境，并进一步展示引用、记录和原始内容，让结果有前因后果。可把这种结构概括成：

用户处境 → 一个核心问题 → 真实操作 → 结果 → 支撑结果的原始证据

UI 展示则采用“完整设备 → 页面内点击 → 结果特写”的三级镜头接力：先让观众看清手机或设备全貌和当前页面，再跟着真实点击推近，最后在关键结果处停稳约一秒或更久，让人读得完。不要为了节奏把界面切成无法辨认的碎片，也不要每讲完一句话就清空画面、让设备重新飞入。让同一台设备和界面状态连续变化，观众更容易理解操作发生在哪里。

生活实景负责迅速说明使用场景，不应长时间抢走产品本身的注意力。原文建议让咖啡馆、通勤、办公等生活画面点到即止，接下来尽快回到真实产品操作。生成镜头也尽量采用单机位、简单动作；多机位切换、多人连续表演等复杂要求，可能让人物和画面连续性变得不稳定。

真实 UI 与生成实景怎样融合

视频生成模型容易把屏幕上的文字、图标和界面细节画错。原文的合成办法是先生成设备屏幕保持黑色的生活底片，再把产品自己的真实 UI 逐帧合到屏幕显示区域，而不是让模型直接生成软件界面。

基本处理步骤如下：

  1. 定位屏幕内侧四角：先在清晰帧中标出屏幕显示区的四个内角，避开金属边框和圆角外壳，并人工确认坐标。
  2. 跟踪并做透视变换：随着设备移动，逐帧更新四角位置，对 UI 做透视变形；对轨迹轻度平滑，减少单帧抖动。
  3. 处理遮挡关系：手指经过屏幕时要作为前景遮罩盖住 UI，离开后再显露界面变化，避免图层穿帮。
  4. 保留玻璃反光：根据素材尝试滤色等混合方式，让屏幕原有的环境亮部透出来，而不是用完全不透明的界面盖住玻璃。
  5. 匹配底片质感：按实景的景深、锐度和颗粒调整合成层，避免 UI 过分锐利、看起来像贴纸。

不是每个镜头都值得做这种复杂合成。可以先挑一段几秒的方向样片，检查透视、手指遮挡和反光效果，再决定是否扩展到其他场景。生成时也尽量让设备保持稳定，把明显动作放在屏幕以外，能让后期跟踪更可靠。

功能介绍片：真实界面、旁白和屏幕文字各司其职

介绍功能不一定需要生成实景视频。原文展示了一种低成本路线：浅色背景、真实 UI、清楚的标题和自然口播，通过代码动画突出操作过程。

避免把旁白、字幕和屏幕大字逐字重复。可以让三者分工：旁白解释完整语境，屏幕标题只保留几字重点，真实界面负责演示操作与结果。到了需要读屏幕细节时，收起外围大字，把注意力留给 UI。

配音应直接用真实产品文案试听，而不只听语音库的演示样本。作者还区分了屏幕显示稿和 TTS 口播稿：产品名在画面上保持正确拼写，口播文本则可按语音模型的实际发音需求调整。确定声线后记录 voice、语速等参数；新增或修改旁白时，先生成音频并测出时长，再按真实语音时间安排镜头。觉得太长时优先删减文案，而不是整条音轨加速。

品牌片：用一个视觉概念留下记忆

品牌片不需要解释每个按钮，可以集中呈现一个形状或一种情绪。原文举的做法之一是分析 Logo 的几何特征，再寻找天然具有相似轮廓的生活物件，用静态图片和代码快切形成联想。这种方案不必生成动态视频，制作成本也更容易控制。

另一种做法是让生活场景成为背景，通过代码控制遮罩逐步展开或收拢，形成品牌标志的视觉节奏。若需要把人物从背景中分离出来，前景人物和窗口背景要来自同一段视频的同一帧，否则手部动作和桌面边缘容易错位。

从 15 秒样片开始，按六轮逐步定稿

原文建议不要一开始就制作 60 或 90 秒成片，先选一项核心功能做 15 到 20 秒小样。每轮只确认一个阶段，前一轮的交付物通过后再继续：

  1. 准备素材：提供项目目录、Logo、发布渠道、画幅、目标观众和一句话价值主张；让 Agent 运行产品，导出干净的真实界面与演示数据。
  2. 先排静态画面：把旁白、屏幕短字和画面操作排成三栏表，先检查关键帧、同一设备的连续性和视觉基调。
  3. 试听并测时长：用真实台词比较声线，确定口播稿后测出关键动作在音频中的时间点。
  4. 导出第一版 MP4：用 Remotion 等工具合成一段能完整播放的小样，检查黑帧、字幕遮挡、操作时机和结果停留时间。
  5. 锁定满意部分，单点修改：把反馈落到具体秒数和问题，保留上一版，只改最影响观看的一处并做新旧对比。
  6. 沿样片扩展：小样通过后再补开场、其他核心场景和结尾。新增旁白先录音测时长，新增实景镜头单独列清单。

这种阶段式协作让每轮都有看得见的交付物，也避免“再优化一下”触发整片重做。中途更换 Agent 或会话时，保留一份简短交接记录，写清已确认的画面、锁定的声线参数、素材目录和下一轮唯一修改目标。

开工前的安全与预算边界

宣传片会读取代码、截取界面、生成演示数据并调用可能收费的服务。建议只提供当前项目需要的目录和资料，演示数据使用虚构内容，截图前检查邮箱、用户姓名、客户记录等私人信息。API Key 放在受控的本地环境变量或密钥管理工具里，不要写进提示词、视频素材、仓库或交接文档。

每次调用付费模型前，确认模型、时长、分辨率和预算上限，并先生成一条小样供人确认。模型名称、参数、接口和价格会变化，应在实际制作时核对当前服务页面。Agent 可以准备任务和预估成本，但不应在没有人工确认时自动充值或持续扩大生成批次。

发布前检查

  • 观众、发布位置、画幅和一句话核心价值已确定。
  • 视频围绕一个具体使用情境，而不是逐项报功能。
  • 真实 UI 能看懂，关键结果有足够停留时间。
  • 旁白、屏幕短字和界面内容没有互相重复或冲突。
  • 生成实景与合成 UI 的透视、遮挡、反光和连续性已检查。
  • 音轨按实际语速与时间戳排好，音画同步。
  • 演示数据不包含真实用户隐私，Logo 与素材具备使用授权。
  • 预算和付费调用经过确认，最终 MP4 从头到尾播放复核。

总结

这套制作方法的核心不是寻找一条万能提示词，而是把叙事、真实产品证据、生成画面和代码合成放进一条可审阅的流程：先选一个目标和具体案例，再确认真实界面，接着用少量生成素材补足场景，最后根据真实音频和播放效果细调时间线。

先完成一条可播放的 15 秒样片，远比一次铺开长片更容易发现产品叙事和画面衔接的问题。把决定拆成小轮次，让每次修改都能对照旧版本，创作者就能把 AI 当作制作团队来协作，同时保留对内容、预算和最终交付的控制。
