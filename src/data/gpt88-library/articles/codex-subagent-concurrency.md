Codex 可以将独立任务分配给多个子智能体并行处理。本文默认推荐配置为 8 个子智能体，客户可以根据任务规模、响应速度和额度预算自行调整。

8 是本站教程采用的推荐值，并非 OpenAI 官方固定默认值或最大值。未设置该项时，由 Codex 选择默认数量。此项只调整子智能体数量，不会修改模型或推理强度。

## 1. 找到配置文件

使用文本编辑器打开用户配置文件 config.toml。修改前先保存一份备份，保留原有的模型、API 地址和密钥相关配置。

| 系统 | 默认配置文件位置 |
| --- | --- |
| Windows | %USERPROFILE%\.codex\config.toml |
| macOS | ~/.codex/config.toml |
| Linux | ~/.codex/config.toml |

Windows 用户可将上述路径粘贴到文件资源管理器地址栏。如果设置过 CODEX_HOME 环境变量，请打开该变量指向目录中的 config.toml，以实际配置目录为准。

## 2. 默认设置为 8 个子智能体

如果文件里还没有 [agents] 分节，可在文件末尾另起一行加入以下内容：

~~~toml
[agents]
max_concurrent_threads_per_session = 8
~~~

数字 8 表示允许同时打开的子智能体线程上限为 8，不包含主智能体。它是并发上限，不是强制每个任务都启动 8 个，也不是整段聊天累计只能创建 8 个。

如果已经存在 [agents]，只需在该分节中添加或修改下面这一行，不要重复创建 [agents]：

~~~toml
max_concurrent_threads_per_session = 8
~~~

这一行必须位于 [agents] 下方、下一个 [分节名称] 之前，不要放进 [agents.某个角色] 等其他分节。max_threads 是仍兼容的旧名称；本教程统一使用新名称，已有配置只保留一种写法即可。原有的顶层 model、model_provider 等配置应留在原位置。

## 3. 按自己的需求调整数量

| 需求 | 可尝试的设置 |
| --- | --- |
| 任务较少，优先控制并行消耗 | 4 |
| 日常开发，先使用本站推荐配置 | 8 |
| 独立子任务较多，希望进一步并行 | 在 8 的基础上逐步调高，并验证实际可用数量 |

调整时只需要把示例中的 8 改成需要的正整数。更多子智能体可能增加同时发生的请求和额度消耗；任务存在先后依赖时，增加数量也不一定更快。实际数量仍受客户端运行环境、模型服务和账户并发限制影响。

## 4. 保存并验证生效

保存 config.toml 后，完全退出并重新打开 Codex，再新建一个聊天进行验证。现有聊天可能继续使用原先分配的限制。

可以发送：“请把这个任务中能够独立完成的部分交给多个子智能体并行处理。”然后在子智能体活动列表中观察实际启动数量。任务较简单时没有开满，并不代表配置无效。

## 5. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 保存后提示重复分节或重复字段 | 检查是否重复添加了 [agents] 或数量字段，合并为一份。 |
| 提示无法识别配置项 | 先更新 Codex，再按当前版本官方说明检查字段支持情况。 |
| 配置为 8，实际启动数量仍较少 | 确认已重启并新建聊天；检查实际加载的配置文件、项目配置覆盖和运行环境限制，任务本身也可能只需要较少子智能体。 |
| 数字越大越好吗？ | 不一定。先从 8 开始，按任务并行程度、稳定性和额度预算逐步调整。 |
