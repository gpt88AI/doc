第一次使用 Codex，建议从一个能在本地运行的小项目开始。这一课的目标是让它找到页面入口、解释数据流、发现可用检查，再完成一处能验证的小改动。完成后，你应当拿到可运行的结果和检查证据。

## 先准备项目与接入

准备已有代码、README 和启动说明。如果项目使用 Git，先查看当前状态，知道哪些文件已有未提交修改。不要为了开始教程清空已有工作。

~~~shell
git status --short
~~~

本站 API 的地址、密钥和模型配置，请先按站内现有的 Codex 接入教程完成。本系列讲接入成功之后怎样做项目。安装客户端与配置 API 是两个步骤；不要把密钥写进项目源码、提示词示例或公开仓库。

选择命令行方式时，先安装 Node.js 并确认终端可用 npm，再安装和启动 Codex。下面第二条命令应在你的项目根目录运行。

~~~shell
npm install -g @openai/codex
codex
~~~

选择桌面方式时，在桌面应用中进入 Codex，打开本地项目文件夹，再开始对话。项目根目录通常包含 README、依赖清单和源码目录，避免只打开某个组件文件所在的子目录。

## 第一步：只读认识项目

把下面的提示词发给 Codex。首次探索先限定为阅读，方便确认它是否找对项目和入口。

~~~text
我刚接手这个项目。请先阅读项目说明、AGENTS.md（如果有）、
依赖清单和主要入口，暂时不要修改文件。
说明项目做什么、页面和接口从哪里进入、数据如何流转。
找出实际可用的安装、启动、构建、检查命令，并标明依据文件。
列出当前未提交改动；后续保留这些改动。
最后推荐一项适合第一次练习的小改动，并说明如何验收。
~~~

检查回答是否引用了真实文件。它应当能解释“页面调用哪个接口、接口返回什么”，而不只是罗列文件夹名称。遇到不清楚的模块，可以继续要求它从一个具体页面沿调用关系追踪。

## 第二步：完成一个小改动

以“订单列表没有结果时补充提示”为例。页面名称和文案要换成你自己的业务；如果项目没有订单模块，就选择已有列表。

~~~text
请为订单列表补充空结果提示：没有匹配订单时显示
“没有找到匹配的订单，请调整筛选条件”。
沿用现有样式和组件，不新增依赖，不改变接口字段。
先确认现有加载、错误、空数据三种状态的处理方式，再实现。
保留当前未提交改动，不提交、推送或部署。
依据项目已有脚本运行与这次修改有关的检查，并给出浏览器验收步骤。
~~~

一个好结果会区分“正在加载”和“查询成功但没有数据”。如果请求失败，也不应显示空结果文案。这样的小任务能帮助你判断 Codex 是否理解了项目的真实行为。

## 第三步：看结果和证据

不要直接假设项目有 `npm test`。JavaScript 项目可以先让 Codex 读取依赖清单中的 scripts，并按锁文件判断包管理器；其他语言则以项目说明和现有检查配置为准。

~~~text
请总结本次改动涉及的文件、用户能看到的行为变化、
实际运行的检查命令和结果。没有执行的检查请说明原因。
给出本地预览地址，以及加载中、请求失败、空结果的验证方式。
~~~

## 验收清单

- Codex 指向了正确的项目入口，并保留已有修改。
- 普通列表仍正常，空结果提示只出现在查询成功且没有数据时。
- 已运行项目中实际存在的相关检查，结果可查看。
- 你亲自在页面确认文案和状态，没有只凭完成声明判断。
## 常见问题

### 提示找不到 codex 命令

先确认 Node.js 与 npm 已安装、安装命令成功，并重新打开终端。如果仍失败，提供完整安装错误，让 Codex 根据实际环境排查。

### 能对话，却读不到项目

确认当前对话绑定的文件夹，或终端所在目录。把项目目录明确告诉它，再要求列出入口文件验证。
