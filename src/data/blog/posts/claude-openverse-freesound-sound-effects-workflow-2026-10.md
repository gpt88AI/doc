> 本文依据[程序员鱼皮的 X 帖子](https://x.com/yupi996/status/2110978294891897173)及配图整理。原帖给出的是一种让 Claude 在剪视频时搜索音效的工作流；库规模是配图发布时的统计，不代表当前实时数量。本文还对 Openverse 的公开音频搜索接口做了只读核验，并补充了素材筛选和授权检查步骤。

剪辑视频时，转场、动作和环境音能明显改变观感，但找素材常常要离开剪辑流程，反复搜索、试听、下载，再手动记录来源。程序员鱼皮分享的做法，是把 Openverse 作为音频检索入口，让 Claude 在需要音效时按关键词搜索，并把范围限定在 Freesound。

核心不是让 AI “随便拿免费音乐”，而是把查找和初筛交给工具，同时保留创作者、原始页面和许可证信息，最后由人决定是否适合这个作品。

![原帖配图：Openverse 音频搜索、Freesound 来源筛选和 CC0 示例](/docs/blog/zh/claude-openverse-freesound-sound-effects-workflow-2026-10/img/2110918849126387712.jpg)

## 工作流拆解

原帖建议把 Openverse 音频 API 的入口告诉 Claude，并说明需要音效时搜索 Openverse、优先挑适合当前视频的结果；如果目标是音效而不是音乐，再补充 `source=freesound` 作为来源过滤。配图里的示例使用 `whoosh` 搜索转场音效，并进一步筛选 `license=cc0`。

可以把这一流程分成四步：

1. **描述画面和声音意图。** 例如“镜头快速转场时需要一个短促、干净的 whoosh，不要带人声，尾音不要盖住旁白”。
2. **搜索并限制素材来源。** 用具体英文关键词搜索，按 `freesound` 等来源筛选；必要时再按许可类型筛选候选。
3. **比较候选素材。** 试听开头、主体和尾音，比较时长、响度、底噪和情绪，不要只根据标题或自动标签选择。
4. **下载后登记来源和许可。** 保存原始素材页、作者、许可证及版本、下载日期和项目用途，并在时间线上标记使用位置。

给 Claude 的需求可以写成一段制作约束，而不是只说“帮我找音效”：

```text
为这个镜头搜索一段适合的音效：描述声音类型、时长、情绪、是否允许人声，以及它要避开的旁白或音乐频段。
优先搜索 Openverse 的音频结果，并限定来源为 Freesound。
先列出候选的标题、作者、原始素材页、许可名称和预览地址供我试听；不要只凭标题自动决定。
下载前确认该条素材的许可是否适用于本项目，并保存署名信息。无法确认时先停下并说明原因。
```

这里刻意保留了“先给人试听与确认”这一步。AI 可以节省寻找入口和整理候选的时间，但不能替代对声音内容、授权条款和最终混音的判断。

## Openverse 接口能提供什么

Openverse 的音频搜索接口会返回搜索结果及其元数据。核验时使用了配图中的查询形式：

```text
https://api.openverse.org/v1/audio/?q=whoosh&source=freesound&license=cc0
```

匿名 GET 请求在核验时可以返回结果；响应中可见标题、作者、来源、许可名称和版本、许可链接、预览地址、原始素材页、文件格式和文件大小等字段。官方文档另有 OAuth 认证流程，并说明认证后可以解锁更高的请求限额。核验时点的匿名响应头显示每分钟 20 次、每日 200 次的限额；这些数值属于当时的服务响应，可能调整，自动化脚本应读取响应状态并做好限流与重试，而不是把数字写死。

这说明“单次搜索不用先申请 API Key”在当前公开接口上可以复现，但它不等于不限量访问，也不等于任何 Claude 环境都能直接联网或下载文件。实际工作流还取决于 Claude 所在产品是否具备网络访问、命令执行或文件写入能力；无法调用工具时，仍可以手动在 Openverse 搜索后把候选信息交给 Claude 做比较。

## 搜得到，不等于拿来就能用

Openverse 聚合的是带有开放许可或公有领域信息的媒体条目，但每一条素材的来源、许可和发布者都可能不同。搜索结果适合发现候选，不构成对权利状态的担保。

下载前至少检查这些项目：

- **许可名称和版本：** CC0、CC BY 等许可的条件不同；不要只看“免费”或颜色标签。
- **署名要求：** CC BY 通常要求以许可规定的方式注明作者、作品、来源链接和许可。即使 CC0 通常不要求署名，保留来源记录仍有利于审计和日后复查。
- **原始素材页：** 回到 Freesound 等来源页面确认当前条目、作者、许可声明和可下载版本一致。
- **第三方权利：** 录音中可能包含他人音乐、表演、品牌或可识别人物声音；开放许可字段不能自动解决所有相关权利。
- **项目用途：** 商业广告、客户交付、影视发行和平台投放可能有额外要求；拿不准时更换素材或取得明确许可。

适合自动化的范围是“搜索、筛选、下载候选并生成署名清单”。建议把最终选用设为人工确认，特别是公开发布或商业项目。下载文件旁可以保存一份小型素材记录：

| 字段 | 记录内容 |
| --- | --- |
| 文件名 | 项目内使用的音频文件名 |
| 作品与作者 | Openverse 显示的标题、作者或账号 |
| 来源 | 原始 Freesound 等素材页面 |
| 许可 | 许可名称、版本与许可链接 |
| 用途 | 对应镜头、时间码和处理方式 |
| 核验时间 | 下载和复核的日期 |

这份记录能让后续改片、迁移项目和回应授权问题更可靠，避免素材只剩一个文件名却找不到出处。

## 音效和背景音乐要分开找

原帖特别提醒，目标是音效时可以限定 `source=freesound`。这是一个实用的检索提示，不是说所有 Freesound 音频都是音效，也不是说其他来源没有合适的音效。仍需通过试听和条目元数据逐个判断。

音效和配乐的需求也不同：

| 需求 | 搜索线索 | 剪辑检查 |
| --- | --- | --- |
| 转场 | whoosh、swoosh、swipe | 起音是否干净，尾音会不会拖长 |
| 点击或界面反馈 | click、tap、notification | 音量是否克制，是否刺耳或过度重复 |
| 环境氛围 | room tone、rain、wind、crowd | 是否循环自然，是否含不需要的语言或突发声 |
| 物体动作 | impact、cloth、door、footsteps | 声音材质是否符合画面，节奏是否对齐 |
| 背景音乐 | genre、mood、tempo | 是否适配完整片段，版权与商业用途是否明确 |

最终混音时还要检查峰值、响度、淡入淡出，以及对白和音乐之间的遮蔽。一个搜索结果再匹配，也可能因为响度或尾音不适合而需要裁剪或换用。

## 数量和额度要按查询时点理解

原帖配图写有 Openverse 音频条目、Freesound 音效、Jamendo 音乐和 Wikimedia 资源库的数量。它们是作者分享时看到的目录规模快照，不应当作今天的实时目录统计。检索结果会随索引、来源接入和过滤条件变化；对实际选材而言，结果是否匹配、许可是否合适，比总条目数更重要。

同样，匿名 API 的请求额度可能变化。少量手动搜索可以从公开接口开始；如果要在应用或自动化流程里持续调用，应先看 Openverse 当前认证和节流文档，按要求注册客户端，并处理 429、网络失败和空结果。不要把客户端密钥放进公开视频项目、提示词、仓库或浏览器端代码。

## 一条实用边界

让 Claude 代为搜音效，可以减少搜索与整理成本，但可信的制作流程仍应保留人的最后一关：试听是否合适，授权是否覆盖目标用途，署名是否正确，混音是否清晰。最好的自动化结果不是“搜到就自动塞进成片”，而是一个带原始链接、许可和试听信息的候选清单，让创作者可以快速做出有依据的选择。
