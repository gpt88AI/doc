## 先看结论：AI 学不会，是用会的

这篇长文的目标不是让读者背完一份工具名词表，而是建立一套可以迁移到新产品上的判断框架：

1. 先理解大模型能做什么、不能做什么。
2. 再学会把任务、背景、例子和验收要求说清楚。
3. 理解 Agent 如何规划步骤、调用工具并在授权范围内执行。
4. 用真实任务反复验证，而不是只看榜单、宣传或别人的推荐。

这四步也解释了为什么“会聊天”不等于“会完成工作”。模型提供生成和推理能力，提示词把需求传给模型，Agent 的工具和权限则决定它能否把结果落到文件、表格或其他实际产物上。

## 一、大模型通识：先建立能力边界

### 1. AIGC 为什么更容易被普通人使用

作者把 AIGC（人工智能生成内容）概括成一个简单的交互：你用自然语言描述想要的结果，AI 生成对应内容。常见输入输出组合包括：

- 文生文：写作、总结、翻译、代码和方案；
- 文生图、图生图：根据描述生成或改造图片；
- 文生视频、图生视频：生成片段或让静态图像产生动态效果。

这和传统的识别、推荐类 AI 不同：用户可以直接用日常语言提出需求，产品再把请求交给一个或多个大模型处理。

### 2. 什么是大语言模型

原文用“海量数据、计算资源和参数”解释“大”，用“主要处理自然语言”解释“语言”。可以把它理解为：经过大量文本、代码和其他数据训练，能够根据上下文生成后续内容的模型。

这个比喻有一个重要的提醒：模型的流畅表达不自动等于事实理解。它可能把高频但错误的说法组合成听起来合理的答案，也可能因为知识过时、上下文截断或缺少关键背景而答错。因此，重要信息仍需要人做判断、交叉核对和验收。

### 3. AI 的优势与局限

作者把优势归纳为信息处理、跨领域入门、内容生成和创意发散；局限则包括幻觉、知识时效性、偏见、复杂推理漏洞、深层语义理解不足和上下文限制。

实际使用时，可以把这份清单变成六个动作：

- 给出明确、具体的任务目标；
- 提供完成任务所需的背景和约束；
- 对关键事实做外部核验；
- 把复杂问题拆成多个阶段；
- 在长对话中定期总结并保存结论；
- 对医疗、法律、财务和生产操作保持更高的人工审查强度。

### 4. 模型没有绝对的“最好”

原文建议从访问条件、价格、速度、上下文长度和应用领域几个维度选择模型。这里最值得保留的不是某个模型排名，而是“模型是否适合你的任务”。上下文容量也不能直接等同于记忆能力：官方标注的 Token 上限，和模型能否在很长输入中准确找回关键信息，是两个不同问题。

最有效的测试方式，是准备自己的测试用例。例如：

| 场景 | 验收标准 |
| --- | --- |
| 写作 | 事实可核对、结构完整、语气符合目标读者 |
| 编程 | 修改范围可控、测试通过、能解释失败原因 |
| 办公 | 字段不漏、格式稳定、人工抽检成本可接受 |
| 长文分析 | 能定位关键证据，而不是只给泛泛总结 |

每次更换模型时记录版本、入口、总耗时、返工次数和最终产出。这样得到的是自己的工作流证据，而不是一次性的“手感”。

## 二、提示词工程：把需求讲清楚

### 1. 高质量提示词的基本公式

作者把提示词拆成两个基本要素：**指令**和**上下文**。指令说明要做什么，上下文说明为什么做、面向谁、有什么限制和参考资料。

例如，“帮我写一篇产品介绍”信息不足；更可执行的版本会说明产品卖点、目标用户、使用场景、文章长度、语气和必须保留的事实。提示词不是越长越好，而是要让任务边界和验收标准足够清楚。

### 2. 六个可复用技巧

1. **明确任务**：用动词说清楚要生成、比较、提取、改写还是执行。
2. **补充背景**：提供目标受众、已有资料、限制条件和成功标准。
3. **给出例子**：让模型模仿你接受的结构、语气或格式。
4. **设定角色**：在确有帮助时指定专家、编辑、老师或审查者视角。
5. **规定格式**：使用 Markdown、表格、JSON 或固定字段，方便后续处理。
6. **调整语言风格**：明确正式、简洁、口语化、严谨或面向初学者等要求。

作者认为“提示词工程已死”的说法过于绝对。模型能力变强后，日常表达可以更自然，但专业任务仍需要清晰目标、上下文、示例和持续修正。变化的是表达方式，不是“把需求讲清楚”这件事本身。

### 3. 从升维提问到逐级降维

原文给出的工作方法适合复杂任务：先让 AI 帮你拆解问题、提出思路和检查维度，再结合真实约束写出具体提示词，随后根据结果继续迭代，最后沉淀成可复用模板。

这比一开始就追求“完美提示词”更稳妥。也可以先让 AI 生成一个 60 分版本，再用实际结果指出哪里需要变更。持续对话不是放弃结构，而是把结构拆到多轮协作中。

## 三、Agent：从回答问题到执行任务

### 1. Agent 的关键区别

普通对话模型可以帮你整理市场资料，但通常还需要你自己把内容填进 Excel。具备相应工具和权限的 Agent，则可能自主搜索、分析、生成文件并把结果交给你。

因此，Agent 的关键不只是“更聪明”，而是拥有一套执行架构：

```text
目标 → 规划步骤 → 调用工具 → 读取/修改数据 → 检查结果 → 交付产物
```

模型像“大脑”，决定如何理解和规划；工具、权限和运行环境决定它实际上能触碰什么。任何 Agent 任务都应明确授权范围、敏感数据边界、停止条件和人工验收点。

### 2. 用三个问题看懂新工具

面对 Claude Code、Codex、WorkBuddy、OpenClaw 等新产品，作者建议从三个维度判断：

1. **谁开发的**：模型厂商和 Agent 产品厂商可能不是同一家公司。
2. **怎么使用**：对话应用、桌面软件、命令行和即时通讯入口各有适用场景。
3. **主要完成什么任务**：通用办公、编程开发或行业垂直任务，对工具和数据连接的要求不同。

同一个产品可能同时拥有网页、桌面和命令行入口；同一种入口也不代表底层模型、工具权限和安全边界相同。因此不要只看产品名称，要看它能否稳定完成自己的真实任务。

### 3. 普通人的学习路径

原文给出的四阶段路径可以压缩为：

- **第一阶段**：学会表达目标、背景和约束；
- **第二阶段**：使用图形界面 Agent 完成一个真实的小任务；
- **第三阶段**：观察它如何规划、调用工具、处理错误和交付文件；
- **第四阶段**：只有在需求出现时，再深入学习编程 Agent、Skills、MCP、远程或定时执行。

没有实际需求时，不必为了追逐工具名词而强行搭建复杂自动化。

## 四、WorkBuddy 实操：用一个任务理解 Agent

原文最后以 WorkBuddy 作为新手入口，建议先配置工作空间、权限和模型，再输入一个具体目标。示例是调研宠物猫高端烘焙粮市场，要求收集 2025—2026 年市场资料、比较猫经济和犬经济、分析传统平台与内容电商指标，并生成 Excel。

这个示例真正值得学习的是任务写法：它同时写出了研究对象、时间范围、比较维度、输出格式和下载位置。无论使用什么 Agent，都可以用同样的结构描述任务。

实践时建议增加三项约束：

- 要求列出来源和数据时间，避免把估算写成事实；
- 要求先给研究计划，确认范围后再执行；
- 要求完成后检查文件是否存在、字段是否完整、结论是否能回到来源。

原文提到的具体模型、免费额度、价格倍率和产品界面会随时间变化，本文不把它们当作当前承诺。使用前应以产品官方页面、当前账户界面和实际权限为准。

## 一张可执行的 AI 入门检查表

开始一个新任务前，可以先回答：

- 我想要的最终产物是什么？
- AI 需要哪些背景、资料和格式要求？
- 哪些内容必须引用来源或人工复核？
- 这个任务需要普通聊天、工具调用还是 Agent 执行？
- Agent 需要什么权限，哪些文件和账号不能触碰？
- 怎样判断任务完成，失败后从哪里恢复？

如果这些问题还答不清楚，继续增加提示词长度通常没有帮助。先把目标和验收标准写清楚，再选择模型和工具。
