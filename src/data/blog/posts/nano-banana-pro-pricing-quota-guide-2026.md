查 Nano Banana API 价格，先别急着记一个“每张多少钱”：现在至少有 Lite、Nano Banana 2、Pro 和旧版四条官方模型行，同一个 `$0.067` 甚至可以代表两种完全不同的购买方式。截至 2026 年 7 月 15 日，只做 1K 且成本优先，可以从 Lite Standard 的 `$0.0336/张` 开始；需要 0.5K—4K 的灵活尺寸，可以先看 Nano Banana 2；只有工作确实需要高级能力，才把 Pro 的 `$0.134/张` 当成起点。

这几条官方图片 API 价格行目前都写着不提供 Free Tier。创建 Gemini API Key 只是获得调用凭证，并不自动附带免费图片；Gemini App 的可用次数、订阅权益和第三方平台积分，也不能拿来改写 Developer API 的每张图价格。能接受异步等待时，再比较 Batch/Flex：便宜不等于适合实时请求，真正该比较的是交付一张可用图片要花多少钱。

## 先把“谁在收钱”分清，价格才有可比性

常见的“API 价格”常把四种账混在一起：Google 官方模型输出费、项目与 API Key、Gemini 消费端产品，以及第三方供应商或网关。它们经常被并列展示，却回答不同问题。

| 看到数字的地方              | 这个数字能回答什么                                    | 不能据此推断什么                          |
|-----------------------------|-------------------------------------------------------|-------------------------------------------|
| Google Developer API 定价页 | 官方模型、模式、分辨率、输出单价与表中 Free Tier 状态 | Gemini App 次数、订阅权益、第三方失败计费 |
| API Key 与 Google 项目      | 哪个项目、凭证和账单账户发起请求                      | “有 Key 就免费生成图片”                   |
| Gemini App 或消费者订阅     | 该 App 内的访问方式和该计划的限制                     | Developer API 每张图片的官方价格          |
| 第三方供应商或网关          | 该平台的余额、模型入口、日志、支持与扣费规则          | Google 官方价，或另一家平台的合同         |

因此，预算表的第一列不应该只有“价格”，而应同时写清模型 ID、分辨率、模式、计费方和核对日期。若页面只写“Nano Banana 每张 `$0.03`”，却没有说明是哪一个模型、是否 Batch、输出多大、向谁付费，这个数字最多只能当线索，不能直接进生产预算。

## 不要从“最强模型”开始，从交付要求反推模型

如果三条当前路线都能完成任务，最稳的选法不是先买 Pro，而是用最低成本路线跑一组受控样本。先写下必须满足的分辨率、参考图要求、文字呈现、风格一致性、编辑能力和交付时限，再决定哪个模型进入测试。

### 只做 1K：先让 Lite 证明自己不够用

Lite 的官方定位和价格都指向低成本 1K 工作：Standard `$0.0336`，Batch `$0.0168`。它适合缩略图、内部预览、低风险素材草案或大量候选图。停止继续测试 Lite 的条件应是可验证的，例如必须输出更高分辨率、关键参考图约束反复失效，或按同一评分表计算后，可用率低到抵消单价优势。

不要因为 Lite 便宜就假设它一定能替代其他路线；也不要因为名称里有 Lite 就不测试。价格判断需要和真实任务绑定，最便宜但大量返工的模型，可能比高价模型更贵。

### 需要多档分辨率：Nano Banana 2 通常是平衡起点

Nano Banana 2 覆盖 0.5K、1K、2K 和 4K，Standard 从 `$0.045` 到 `$0.151`，Batch 从 `$0.022` 到 `$0.076`。它比 Lite 更适合需要分辨率伸缩的工作，也让团队能在同一模型内按成品用途调整成本。

例如，预览阶段先用 0.5K 或 1K，最终入选素材再生成 2K 或 4K，通常比所有候选图一开始都走高分辨率更好控制预算。前提是工作流能保证提示词、输入图、验收标准和版本记录一致，否则你无法知道成本差异来自模型、分辨率还是测试本身。

### 选择 Pro 要有一条可量化的理由

Pro Standard 的 1K/2K 是 `$0.134`，约为 Nano Banana 2 1K Standard 的两倍，也接近 Lite 1K Standard 的四倍。这个溢价并非不合理，但应该由任务来证明：例如特定高级能力是硬要求，或同一批测试中 Pro 的可用成片率足够高，减少了重试、返工和人工筛选。

一个简单的模型资格测试可以这样做：固定 20—50 个有代表性的提示词与输入图，固定输出尺寸和验收标准，让 Lite、Nano Banana 2、Pro 分别生成；记录成功请求数、可用成片数、平均人工处理时间和失败类型。只有通过这组数据，才能回答“Pro 是否值得”，而不是把型号名称当成质量结论。

## Standard 与 Batch/Flex：省下的是等待成本，还是业务价值

模式选择发生在模型选择之后。Standard 适合用户正在页面上等待、设计师需要连续迭代、或下游步骤必须立即得到结果的调用。Batch/Flex 更适合夜间批量生成、素材库刷新、离线评测和可以排队的任务。

价格差很直观：Lite 1K 从 Standard `$0.0336` 降到 Batch `$0.0168`；Nano Banana 2 1K 从 `$0.067` 降到 `$0.034`；Pro 1K/2K 从 `$0.134` 降到 Batch/Flex `$0.067`。但低价行只有在执行方式匹配时才成立，不能按 Batch 做预算，却让产品承诺实时响应。

| 任务信号                   | 更适合的模式             | 预算时别漏掉                 |
|----------------------------|--------------------------|------------------------------|
| 用户或编辑人员正在等待结果 | Standard                 | 交互延迟、并发、重试与超时   |
| 成百上千张素材可排队处理   | Batch/Flex               | 完成窗口、失败回收、结果对账 |
| 先生成候选，再人工筛选     | 视时限而定，常可用 Batch | 被淘汰图片仍是工作流成本     |
| 线上链路和离线刷新同时存在 | 两套模式分别核算         | 不要用离线低价掩盖线上成本   |

如果团队兼有实时与批量工作，最好分别建两个成本池。线上池按 Standard 的峰值请求和重试估算；离线池按 Batch/Flex 的任务量、完成窗口和失败重跑估算。这样既不会高估所有请求，也不会把低价模式错误承诺给实时用户。

## 单价只是起点：把预算换成“每张可用成片”

采购表只写调用次数，会把最常见的成本藏起来：某个模型虽然单价低，却需要更多尝试才能得到可交付结果。更实用的公式是：

`每张可用成片的有效成本 = 列表单价 ÷ 可用成片率`

假设 Nano Banana 2 1K Standard 单价为 `$0.067`，100 次请求最终只有 80 张达到验收标准，可用成片率为 80%，有效成本就是 `$0.067 ÷ 0.80 = $0.08375`。剩余 20 张不是“免费失败”，它们已经进入模型费用、运行时间或人工复核成本。

### 反推：预算固定时最多能接受多少次尝试

同一个公式也可以倒过来用。若给 1K 图片的输出预算是 `$100`，按列表价可支持约 2976 次 Lite Standard、1492 次 Nano Banana 2 Standard，或 746 次 Pro Standard。若目标不是“尝试次数”而是 1000 张可用成片，就要再除以实测可用率。

例如，Lite 的可用率为 60%，要交付 1000 张就需要约 1667 次尝试，列表输出费约 `$56.01`；Nano Banana 2 的可用率为 85%，约需 1177 次，列表输出费约 `$78.86`。Lite 仍然更便宜，但差距已经不是单价表上的两倍。若还要为低可用率增加人工修图，结论可能继续变化。

### 带参考图时单独加输入成本

Pro 当前价格行把图片输入列为约 `$0.0011/张输入图`。如果 1000 次请求每次带一张参考图，输入部分约多 `$1.10`；每次带三张，则约多 `$3.30`。这笔钱相对 4K 输出可能不大，但在大量低成本调用中不应被隐藏。输入图数量、输出尝试、可用成片和人工复核最好分别记账。

## 旧版 `gemini-2.5-flash-image`：认得旧账，但别把它当新项目默认值

旧版模型仍会出现在代码、账单和历史教程里。当前表中它的 Standard 输出是 `$0.039`，Batch 是 `$0.0195`，Priority 是 `$0.0702`；Google 的图片生成指南建议旧版用户迁移到 Nano Banana 2 Lite。

迁移不应只是改一行模型 ID。先从生产流量抽出一组有代表性的提示词、输入图和失败案例，固定分辨率与验收规则，让旧版和 Lite 并行测试。对比可用成片率、缺失能力、等待要求、延迟和总成本，再逐步切换。若 Lite 的 1K 边界不符合任务，测试结果也可能指向 Nano Banana 2，而不是强行迁移到最低价路线。

同时保留旧模型名称与旧价格标签，才能解释历史账单。不要把旧版的 `$0.039` 写成 Nano Banana 2 的价格，也不要把 Priority `$0.0702` 当成 Pro 的价格；相近数字不代表同一模型或同一种执行模式。

## 第三方价格可以比较，但必须先换成同一把尺子

第三方供应商可能提供本地支付、统一日志、兼容接口、客服或更易管理的余额，这些都可能是合理价值。但它给出的“每次调用”“积分”或套餐价属于那家平台，不能直接和 Google 官方每张输出并排，除非先把计费事件与模型身份对齐。

| 供应商报价需要证明什么 | 采购前应拿到的证据                                                 |
|------------------------|--------------------------------------------------------------------|
| 实际模型               | 请求日志、响应字段或后台记录能区分 Lite、Nano Banana 2、Pro 与旧版 |
| 计费事件               | 是按请求、成功任务、返回图片、积分，还是其他单位扣费               |
| 失败和重试             | 超时、审核失败、空响应、隐藏重试分别怎样记账                       |
| 分辨率和模式           | 价格对应 0.5K/1K/2K/4K，以及实时或异步执行                         |
| 吞吐与排队             | 在你的真实负载下验证并发、队列、超时和完成窗口                     |
| 日志与支持             | 订单、发票、日志、工单和退款流程能否用于生产对账                   |
| 数据与权利             | 输入图保存、删除、隐私、输出权利与商用条件由谁负责                 |

先用 20—50 个固定测试样本验证供应商，再比较“每张可用成片成本”。不要用未核实的“不限速”“不封号”“失败不扣费”或稳定性承诺替代证据。需要评估供应商路线时，可继续看 [Nano Banana Pro API 路线验证指南](/docs/blog/)；Google 官方基线与供应商合同应分别核算，不能互相背书。

## 从需求到采购表，只要走完这六步

1.  **写清输出要求。** 先定 0.5K、1K、2K 或 4K，是否带参考图，哪些能力是硬要求，多久必须返回。
2.  **从最低可行模型开始。** 只需 1K 先试 Lite；需要分辨率弹性先试 Nano Banana 2；Pro 由能力或实测可用率触发。
3.  **用同一批样本测试。** 固定提示词、输入图、参数与验收表，不要给不同模型不同难度的题。
4.  **分开实时与批量。** 交互请求按 Standard 核算，可等待工作再用 Batch/Flex。
5.  **记录可用成片率。** 用列表单价除以可用率，再加输入、重试、人工和第三方费用。
6.  **标注价格来源与日期。** 每个数字旁保留模型、模式、分辨率、计费方和核对日期，价格变化时只需更新对应行。

如果最终问题变成“它是否比另一套图像 API 更适合”，不要只对比最低单价。把能力、尺寸、参考图、可用率、执行模式和迁移成本一起放入测试，进一步可参考 [GPT Image 2 与 Nano Banana Pro 对比](/docs/blog/)。

## 常见问题

### 现在最便宜的官方 Nano Banana API 是哪一个？

截至 2026 年 7 月 15 日，当前家族里最低的官方图片输出行是 Nano Banana 2 Lite 的 1K Batch，每张 `$0.0168`；若需要交互式 Standard，Lite 1K 是 `$0.0336`。两者都要先确认 1K 和能力范围符合任务。

### Nano Banana 2 API 每张图片多少钱？

`gemini-3.1-flash-image` 的 Standard 价格为：0.5K `$0.045`、1K `$0.067`、2K `$0.101`、4K `$0.151`。对应 Batch 为 `$0.022`、`$0.034`、`$0.050`、`$0.076`。

### Nano Banana Pro API 每张图多少钱？

`gemini-3-pro-image` 的 Standard 1K/2K 为 `$0.134`，4K 为 `$0.24`；Batch/Flex 1K/2K 为 `$0.067`，4K 为 `$0.12`。这些是官方输出基线，不含所有输入、重试、可选功能或第三方费用。

### 官方 Nano Banana 图片 API 有免费额度吗？

当前定价页列出的 Lite、Nano Banana 2、Pro 和旧版图片输出行，Free Tier 都是“不提供”。这句话只回答 Developer API 表格，不等于 Gemini 消费端产品、订阅、试用或第三方积分都不存在。

### 创建 Gemini API Key 会送免费图片吗？

不会因为创建 Key 就自动获得免费图片权益。API Key 是项目凭证；是否计费、按哪个模型行计费，要看项目、官方价格和具体请求。App 次数或供应商余额属于另一套账。

### 1000 张 1K 图片大约多少钱？

### 为什么 Nano Banana 2 和 Pro 都会出现 `$0.067`？

因为它们不是同一行。Nano Banana 2 的 1K Standard 是 `$0.067`，Pro 的 1K/2K Batch/Flex 也是 `$0.067`。报价时必须把模型、模式、分辨率和计费方一起写出来。

### Batch/Flex 是否总比 Standard 更值得？

只有任务能接受异步、灵活或批量执行时才值得。若用户正在等待、下游链路必须实时继续，Standard 的业务价值可能高于单纯节省一半输出费。

### Lite 比 Nano Banana 2 便宜，为什么不全部改用 Lite？

Lite 当前是 1K 低成本路线，任务可能需要更多分辨率、特定能力或更高可用率。先用同一组样本测试；只有当 Lite 满足验收标准时，低单价才转化为真实节省。

### 旧版 `gemini-2.5-flash-image` 还应该继续用吗？

Google 建议旧版用户迁移到 Lite，但生产环境应先做并行评测。若 1K 与能力边界不合适，也要把 Nano Banana 2 纳入候选。保留旧模型标签用于解释历史代码和账单。

### 第三方的低价可以直接和 Google 官方价比较吗？

不能直接比较。先确认实际模型、分辨率、模式、计费事件、失败与重试规则，再把报价换成每张可用成片成本。第三方价格只代表该平台自己的合同。

### 图片输入也收费吗？

Pro 当前定价行把每张输入图列为约 `$0.0011`。多参考图、多次尝试和其他可选功能应单独记录；输出单价不是整条工作流的总价。

### 价格表多久需要重新核对一次？

模型名称、价格、模式、Free Tier 和可用性都可能变化。正式采购、发布报价或扩大调用量前，应回到 Google 官方定价与图片生成文档重新核对，并在内部预算表保留检查日期。
