## 先回答一个问题：你到底要解决什么任务

AI 硬件选购最容易犯的错误，是先问“哪台机器更强”，再试图给机器找任务。更可靠的顺序是先记录自己的工作负载：

| 任务 | 首先观察什么 | 常见瓶颈 |
| --- | --- | --- |
| 本地运行语言模型 | 模型权重、上下文长度、量化方式 | 可用内存、内存带宽、推理框架 |
| 图像与视频生成 | 显存、算子和插件兼容性 | 显存容量、显卡生态、单张耗时 |
| 微调与实验 | 数据规模、训练框架、多卡需求 | 显存、CUDA/框架支持、散热和稳定性 |
| Agent 与开发 | 工具链、容器、编译和调试 | 软件兼容性、磁盘、并发和可观测性 |
| 日常办公加少量 AI | 噪音、功耗、可靠性 | 交互体验、总成本、维护复杂度 |

把任务写成可测量的句子，例如“每天本地处理 50 个文档，单个任务允许等待两分钟，需要保留原文不上传云端”。这比“想跑大模型”更能指导硬件选择。

## 三条路线，先看定位再看参数

视频把 M5 Ultra、RTX 5090 和 DGX Spark 放在一起比较，价值不在于给出一个永远有效的排名，而在于提醒我们：它们代表的是不同的产品路线。

### M5 Ultra：把桌面体验和统一内存放在一起

Apple 芯片路线通常适合重视整机安静、系统体验、开发工具和统一内存使用方式的人。CPU、GPU 与其他计算单元共享内存，能够让一部分需要较大模型上下文的本地实验少一些显存分配烦恼。

选择这条路线前，要重点确认三件事：目标模型是否有可用的 Metal/MLX 等后端，常用 Python 包和容器是否支持当前系统，以及你的任务是不是更看重整机体验而不是 CUDA 生态。能运行一个模型，不代表所有插件、训练脚本和量化工具都能无修改运行。

### RTX 5090：以显卡生态为中心的本地路线

独立显卡路线的优势通常来自成熟的 GPU 软件生态、显式的显存边界和大量现成教程。对图像生成、视频生成、CUDA 训练或已经围绕 NVIDIA 优化的工具链，生态兼容性往往比纸面峰值更重要。

它也要求购买者承担更多系统工程：机箱空间、电源、散热、噪音、驱动版本和显存不足时的降级策略都要提前考虑。桌面显卡的规格不能直接转换成模型吞吐，真实结果还取决于模型、精度、批量大小、上下文和推理框架。

### DGX Spark：面向 AI 实验的专用工作站思路

DGX Spark 代表的是更聚焦 AI 的桌面系统：购买者希望拿到一个相对完整的开发环境，而不是从零组装显卡、主机、驱动和依赖。它适合把“本地模型实验”作为主要工作，而不是偶尔运行一次推理。

但专用设备也意味着更强的路径依赖。购买前应确认目标框架、模型格式、外设和系统版本是否在官方支持范围内；如果你需要的是通用游戏、视频剪辑或大量已有 CUDA 教程，专用工作站未必是最省事的选择。

## 先做兼容性清单，再比较跑分

每台候选设备都可以按下面的顺序检查：

1. **模型能否加载**：权重大小、量化格式、上下文长度和运行时是否匹配可用内存。
2. **框架能否运行**：确认 PyTorch、MLX、TensorRT、llama.cpp、ComfyUI 或你的实际工具支持目标系统。
3. **插件能否安装**：图像和视频工作流常依赖自定义节点，节点支持的后端可能比主程序更窄。
4. **任务能否持续**：一次跑通不等于能连续工作，要观察温度、降频、内存回收和长时间稳定性。
5. **结果能否复现**：记录模型版本、精度、分辨率、上下文、批量、驱动和软件版本，否则不同机器之间无法公平比较。

一个简单的测试记录表如下：

| 项目 | 记录内容 |
| --- | --- |
| 输入 | 固定提示词、文档集或数据集 |
| 模型 | 完整模型名、版本、量化/精度 |
| 参数 | 上下文、输出长度、分辨率、批量 |
| 时间 | 首 token、完整结果、连续运行时长 |
| 质量 | 任务正确率、人工返工、图像缺陷 |
| 系统 | 内存/显存占用、温度、功耗、错误日志 |

## 不要把“能装下”当成“适合生产”

硬件选型至少有四个层次：

- **能启动**：模型或工作流可以加载并产生一次结果。
- **能使用**：单次延迟、质量和交互体验达到个人预期。
- **能持续**：长时间运行不频繁崩溃、不因温度或内存回收失去稳定性。
- **能交付**：有日志、备份、权限、版本锁定和失败后的回退方案。

如果只是体验新模型，“能启动”可能已经足够；如果要给客户交付服务，就必须把电费、维护、数据保护、并发和故障处理算进去。硬件采购是一项系统决策，不是把参数表中最大的数字加粗。

## 用总成本而不是裸机价格做判断

本地设备的成本至少包含：

```text
总成本 = 设备折旧 + 电力 + 存储与备份 + 软件维护 + 时间成本 + 失败成本
```

设备折旧可以按预期使用年限估算；电力要看长期负载，而不是只看电源额定功率；存储和备份会随着模型、数据集和生成素材增长；软件维护则包括驱动、依赖、插件和系统升级。

还要把自己的时间算进去。如果为了省云端调用费，每周都要花数小时修复环境、迁移依赖和清理磁盘，那么“本地免费”并不是真正的低成本。反过来，如果数据不能离开内网，或者需要反复批量处理，本地设备的控制权可能足以抵消维护成本。

## 先用云端验证，再决定是否买机器

当你还没有稳定的任务样本时，不建议只凭想象购买硬件。可以先用云端模型完成一小批真实工作，记录质量、延迟、调用量、人工返工和可接受成本，再判断是否需要本地化。

对于需要比较多种模型和路线的任务，可以先通过 [GPT88 统一大模型接口](https://gpt88.cc) 做低成本的模型验证：保持输入和验收标准不变，比较不同模型的结果与费用，再决定本地设备要解决的是隐私、延迟、批量成本，还是单纯的实验兴趣。GPT88 的实际模型权限、线路和计费以当前控制台为准，验证结果也不能替代对目标硬件的真实压测。

## 三种常见购买结论

### 适合买 M5 Ultra 的情况

- 你重视安静、稳定的桌面工作体验；
- 主要任务是开发、文档处理和本地推理；
- 目标工具明确支持 Apple 芯片和对应加速后端；
- 你愿意接受部分 CUDA 工作流需要替代方案。

### 适合买 RTX 5090 的情况

- 主要使用图像、视频、CUDA 或 NVIDIA 优化工具；
- 你需要明确的独立显存，并愿意自己维护主机；
- 已经确认模型、插件和驱动版本能够配合；
- 机箱、电源、散热和噪音都有现实的安置方案。

### 适合买 DGX Spark 的情况

- 本地 AI 实验是核心需求，而不是偶尔尝试；
- 你希望减少从零搭建 AI 工作站的系统整合工作；
- 目标模型与框架在官方支持范围内；
- 能接受专用设备的路径依赖，并愿意核对供应与售后条件。

## 最终检查清单

购买前，把下面的问题全部写出答案：

1. 我的前三个真实任务是什么？每周运行多少次？
2. 模型权重、上下文和数据集需要多少内存？
3. 关键工具依赖 Metal、CUDA、其他后端，还是只需要 CPU？
4. 需要离线、内网或本地保存哪些数据？
5. 单次延迟、批量吞吐和人工返工的目标分别是多少？
6. 设备出问题时，任务能否切换到云端或另一台机器？
7. 三年总成本是否低于直接调用云端的成本？

如果这些问题还答不上来，先用真实任务做一周记录，再谈型号。最好的 AI 硬件不是排行榜第一名，而是能在你的软件、数据、预算和维护能力之间形成闭环的那一台。
