ChatGPT 图片生成被挡住时，先不要套一个固定额度表。真正决定动作的是你看到的提示：普通等待、`720 小时` 或 `30 天` 长等待、政策拒绝、空白或失败生成、OpenAI 状态异常，还是代码里的 API 429。普通等待按产品内重置时间处理；长等待要按账号状态症状留证；政策拒绝要改请求；生成失败先查状态；API 429 则进入 OpenAI Platform 的项目、模型、用量层级和 Limits 页面。

截至 2026 年 7 月 10 日，OpenAI 公开帮助文档说明 ChatGPT Images 2.0 可用于所有套餐，Images with thinking 可用于 Plus、Pro 和 Business。Free Tier FAQ 还明确区分了文本模型限制和图片创建工具限制；达到图片工具限制后，应等待产品显示的后续可用时间。OpenAI 仍没有公布一张稳定的 Free、Plus、Pro 图片张数表，因此产品内提示比旧的固定 quota 说法更可靠。

Free 用户看到图片创建限制时，应以产品显示的下一次可用时间为准，不要用文本模型的时间窗口反推图片额度。

| 你看到什么 | 可能归属 | 第一安全动作 |
| --- | --- | --- |
| ChatGPT 显示普通等待或冷却 | 应用侧使用限制或当前容量状态 | 等产品内显示的重置时间，避免连续盲重试 |
| `720 小时` 或 `30 天` | 已报告的长等待或账号状态症状 | 截图、记录套餐和平台，再判断是否联系支持 |
| 内容或安全拒绝 | 请求本身触发政策 | 改写请求，不要等 quota |
| 空白、卡住、失败 | 服务状态或临时请求失败 | 查 [OpenAI Status](https://status.openai.com/) 后再重试 |
| HTTP 429、`rate_limit`、quota | OpenAI API 项目、模型、组织、用量层级或账单 | 看错误正文、headers、项目和 Limits 页面 |

停止规则：不要把 VPN、清 Cookie、开新账号、脚本连点或"无限量"承诺当成主方案。这些动作可能让账号状态和支持证据更难判断。

## 先判断是哪一种限制表面

最有用的问题不是"我还能生成几张图"，而是"哪一个计数器或安全系统挡住了这次请求"。ChatGPT 应用冷却、长等待、政策拒绝、服务失败和 API 429 都会让人感觉"图片被限制"，但它们没有同一个重置时间，也没有同一套修法。

| 表面 | 含义 | 先做什么 | 不要做什么 |
| --- | --- | --- | --- |
| 应用冷却 | 当前账号、模式、套餐或容量下暂时不能继续生成 | 按产品内重置时间等待，然后只发一次干净请求 | 不要在多个标签页反复点 |
| `720 小时` 长等待 | 可能是账号状态、权限、风险或容量相关症状 | 截图并记录使用量、套餐、平台和时间 | 不要写成官方月度 quota |
| 政策拒绝 | 请求内容不允许以当前形式生成 | 去掉受限元素，改成更安全的视觉描述 | 不要等额度重置 |
| 生成失败或卡住 | 可能是服务健康或瞬时后端失败 | 查状态页，健康后再试 | 不要把所有失败都当额度耗尽 |
| API 429 | 代码请求触发了 API 侧限制或账单/项目边界 | 查 error body、headers、模型、项目和 Limits | 不要假设 Plus 或 Pro 会提高 API 项目限制 |

这个顺序能避开旧表格的陷阱。ChatGPT 应用侧限制会随套餐、功能、账号状态和容量变化；API 限制由模型、组织、项目、用量层级和账单控制。社区讨论可以帮你识别 `720 小时` 这类提示，但不能直接替代 OpenAI 的政策或账号结论。

## OpenAI 当前确认了什么

OpenAI 的 [Images in ChatGPT FAQ](https://help.openai.com/en/articles/11084440-chatgpt-images-faq) 是判断 ChatGPT 图片体验的主锚点。截至 2026 年 7 月 10 日，它说明 ChatGPT Images 2.0 可用于所有套餐，Images with thinking 可用于 Plus、Pro 和 Business。[Free Tier FAQ](https://help.openai.com/en/articles/9275245-chatgpt-free-tier-faq) 还说明，图片创建有独立于文本模型限制的工具限额；达到后，需要等到 ChatGPT 显示的后续时间再使用。

可用性不等于固定额度。安全写法应该是：

| 说法 | 处理方式 |
| --- | --- |
| "ChatGPT 可以生成图片。" | 可以，但受套餐、功能、安全和容量影响。 |
| "OpenAI 公布了 Free、Plus、Pro 的固定张数。" | 截至 2026 年 7 月 10 日，公开 ChatGPT 帮助没有给出稳定张数表。 |
| "Images with thinking 所有套餐一样。" | 不要这样写；按套餐和 rollout 处理。 |
| "旧的 Plus 或 Free 数字仍然有效。" | 除非 OpenAI 当前公开同一数字，否则不要依赖。 |

所以，真正要读的是产品内提示。ChatGPT 告诉你等多久，就按那个重置时间；提示政策拒绝，就改请求；多人同时失败，就查状态；代码返回 429，就离开 ChatGPT 套餐假设，进入 API 证据路径。更宽的命名和 GPT Image 2 API 路线可以看 [ChatGPT Images 2.0](/docs/blog/chatgpt-images-2-0/)，当前问题先按受限恢复处理。

## 普通冷却和 720 小时长等待

如果只是普通等待，先按产品内显示的时间处理。不要打开多个窗口、反复提交同一提示词。盲目重试会污染时间线，也可能让账号状态更难解释。

`720 小时` 或 `30 天` 要单独处理。这类提示已经在多地用户讨论里出现，付费账号也有相关反馈，但除非 OpenAI 明确把它写成政策，否则不要把它当成官方月度上限。更稳妥的说法是：这是一个长等待或账号状态症状，需要证据包，而不是猜测。

准备这些内容再升级：

| 证据 | 为什么重要 |
| --- | --- |
| 完整提示截图 | 支持需要看到原始等待文字 |
| 套餐、workspace 或账号类型 | Plus、Pro、Business、团队状态可能不同 |
| 时间戳和时区 | 区分滚动窗口、事故和账号事件 |
| 平台和应用版本 | Web、iOS、Android、桌面端可能不同 |
| 近期大致图片用量 | 判断长等待是否和实际使用冲突 |
| 提示词类型 | 区分额度、政策敏感和安全拒绝 |
| OpenAI Status 状态 | 避免把服务事故误判成账号问题 |

当长等待和低使用量明显冲突、多个设备都复现、付费账号表现和产品提示不一致时，再联系支持。描述要短、准、可复现，不要提交敏感图片、完整私人提示词或无关账号资料。

## 政策拒绝和生成失败不是一回事

政策拒绝不是 quota 问题。ChatGPT 如果说明请求不能生成，等待重置不会让同一个请求变安全。处理方式是移除受限对象、受保护的真人相似性、不安全指令或过于具体的敏感要求，用更通用的视觉结果表达目标。

生成失败或卡住也不能直接等同于 quota。转圈不出图、空白图、通用错误提示，都应该先看服务健康。OpenAI 状态历史里有过影响 ChatGPT 和 API 的图片生成错误率事件；历史事件不证明当前事故，但说明状态检查必须在分支里。

建议顺序：

1. 读完整提示。
2. 如果是政策语言，先改请求。
3. 如果是通用失败，查 [OpenAI Status](https://status.openai.com/)。
4. 如果有活跃事故，等待恢复并保留时间。
5. 如果状态健康且同样失败重复出现，再换一个干净对话或平台做一次对照，然后留证。

不要一次改太多变量。浏览器、网络、提示词、套餐和账号同时改变，成功了也不知道是哪一步有效。

## API 图片限速要单独处理

OpenAI 的 [image generation rate-limit help article](https://help.openai.com/en/articles/6696591) 是 API 侧说明。它写明图片 API 限制取决于模型和用量层级，具体值要到账号的 Limits 视图查看。[OpenAI API rate-limit guide](https://developers.openai.com/api/docs/guides/rate-limits) 也把限制放在组织、项目、模型和用量层级里，而不是 ChatGPT Plus 或 Pro 的应用套餐里。

这能避免一个常见误判：ChatGPT Plus 或 Pro 可能改善应用内体验，但不会自动提高 OpenAI Platform 项目的 API 限制。代码里看到 HTTP 429、`rate_limit`、`insufficient_quota` 或 quota 文字时，就按 API 请求诊断。

| API 证据 | 解决什么问题 |
| --- | --- |
| HTTP 状态和错误正文 | 是速率压力、quota、账单还是权限 |
| error `type` 和 `code` | 是 rate limit、insufficient quota 还是其他边界 |
| 模型名 | 是否调用了预期图片模型 |
| 组织和项目 | 是否看的是发请求的同一项目 |
| 用量层级和账单状态 | 是否具备需要的额度和付款状态 |
| 响应 headers | 是否有 reset 或 remaining 信号 |
| Platform Limits 页面 | 当前账号特定限制是什么 |

API 429 的细节可以转到 [OpenAI API 429 和 insufficient quota 指南](/docs/blog/chatgpt-free-image-generation-limit-complete-guide/)。图片模型是否有免费 API 路线，则要在确认问题属于 API 侧后再看 [GPT Image 2 API 是否免费](/docs/blog/is-gpt-image-2-api-free/)。

如果同一个团队同时使用 ChatGPT 和 API，最好把两条日志分开保存。ChatGPT 侧记录产品内消息、账号套餐、workspace、平台和截图；API 侧记录请求时间、项目、模型、状态码、错误正文、headers、用量层级和账单状态。不要用"Plus 已经付费，所以 API 应该也能继续"来判断，因为这会把两个合同混在一起。真正能定位 API 限制的，是 Platform 项目里的 Limits、billing、usage tier 和错误类型；真正能定位 ChatGPT 应用限制的，是产品界面和账号状态。

这个区分也会影响后续动作：应用侧问题通常是等待、改请求、查状态或找支持；API 侧问题则是降速、排队、换项目配置、补账单或申请更高用量层级。把记录分开，团队复盘时才不会把一次前端等待误写成后端配额事故，也不会把账单问题误当成提示词问题。

## 今天还需要更多图片时怎么办

可行路线取决于分支。不要从"被挡住"直接跳到"绕过"。

| 情况 | 下一步 |
| --- | --- |
| 普通应用冷却 | 等产品内重置，然后发送一次干净请求 |
| 重复生成失败 | 查状态，恢复后再试或简化请求 |
| 政策拒绝 | 改写提示词，让图片请求变成允许的形式 |
| 长等待提示 | 建证据包，只有使用量和等待冲突时再升级 |
| 生产工作需要大量图片 | 评估 API 设计、排队、批处理和成本控制 |
| API 429 | 修请求节奏、模型/项目、用量层级、账单或 quota 状态 |

如果只是临时创作，API 通常不是简单替代品。API 意味着 key、账单、日志、存储、限速、模型路由和政策处理都由你负责。只有产品功能、自动化流水线或批量工作负载，才适合认真设计 API 路线。

如果只是用户端很急，安全选择更少：等重置、减少盲重试、简化请求、查状态、把工作拆到不同时间，或整理证据找支持。这些动作不如"无限量"说法刺激，但能保住账号诊断和后续处理路径。

如果这是团队工作流，不要把个人 ChatGPT 窗口当成唯一生产通道。把今天必须出的图片和可以延后的图片分开，先保留最关键的设计稿、广告素材或说明图，再把批量探索放到重置之后。多人协作时也要记录是谁、在哪个 workspace、用什么提示词类型触发了等待，避免每个人都用不同设备重复试错。这样的记录不一定会立刻提高额度，但它能让后续排查知道是单个账号、团队空间、内容类型还是服务状态造成的阻断。

## 不要信什么

旧 quota 表最容易误导。某个数字可能只对应特定发布窗口、模型、套餐或容量事件，不能自动变成当前政策。Free、Plus、Pro 的图片张数尤其要谨慎。

社区讨论适合识别语言，不适合定义权利。`720 小时`、隐藏月度限制、突然锁定、付费账号不满等讨论，能帮助你描述症状，但不能直接决定 OpenAI 的账号政策。

绕过建议风险最高。不要依赖 VPN 轮换、清 Cookie、无痕窗口、新账号、共享账号、脚本连点或第三方"无限量"承诺。即使某个技巧短暂有效，它也没有解释真实限制表面，反而可能制造账号、安全、账单或支持问题。

任何 provider 说法也要重新验证。速度、稳定性、不封号、无限量、退款、失败不扣费、最低充值和模型覆盖都属于易变承诺。解决 ChatGPT 图片被挡住，不需要这些未验证承诺来转移判断。

更稳的判断方式是把"能不能继续生成"拆成三个问题：账号现在允许什么、这次请求本身是否允许、服务此刻是否健康。只要这三个问题没有分开，任何单一答案都会过度简化。比如同样是 Plus 用户，一个人看到普通冷却，另一个人看到 720 小时，第三个人在代码里收到 429；三者都叫"图片限制"，但修复动作完全不同。读完提示文字、保留证据、少改变量，比立刻寻找捷径更能节省时间。

## 常见问题

### ChatGPT 图片生成有 rate limit 吗？

有。限制可能来自套餐、功能、账号状态、安全系统和当前容量。第一步不是找旧张数，而是按 ChatGPT 当前显示的提示选择分支。

### ChatGPT Free 当前能生成几张图片？

截至 2026 年 7 月 10 日，OpenAI 公开 ChatGPT 帮助没有给出稳定 Free 图片张数表。官方说明图片创建有独立于文本模型限制的工具限额；Free 账号如果显示等待，应按产品给出的后续可用时间处理，不要把文本模型窗口换算成图片额度。如果显示政策拒绝或生成失败，就诊断对应分支。

### ChatGPT Plus 会取消图片限制吗？

不能这样假设。Plus 可能改变应用访问和优先级，但图片生成仍可能受套餐、功能、容量、安全或账号状态限制。

### ChatGPT Pro 图片无限吗？

不要把 Pro 当成无限图片生成。Pro 账号如果出现长等待或普通等待，仍应以产品内提示为准，并在等待和实际使用冲突时保留证据。

### 720 小时等待是什么意思？

把它当成已报告的长等待症状，而不是已确认的官方月度 cap。截图，记录套餐、平台、时间、近期使用、提示词类型和状态页结果，再判断是否联系支持。

### API 429 和 ChatGPT 图片限制一样吗？

不一样。API 限制由模型、组织、项目、用量层级、账单和账号特定限制决定。ChatGPT Plus 或 Pro 不会自动提高 API 项目的限制。

### 应该清 Cookie、用 VPN 或开新账号吗？

不应该。这些都不是可靠恢复步骤，还可能让账号问题更难诊断。按重置提示、政策改写、状态检查、支持证据包或 API Limits 页面处理。

### 如果提示违反政策怎么办？

改写请求。政策拒绝不会因为 quota 重置而消失。移除受限元素，避免受保护真人相似性或危险指令，用更安全的视觉描述表达目标。
