Gemini 提示"无法连接服务器"或"请检查互联网连接，然后重试"，**并不能单独证明是网络、账号、地区或 Google 服务故障**。最快的处理方式不是连续更改设置，而是先确认错误出现在哪个表面：Gemini 网页里、Chrome 错误页、Gemini App，还是你自己的 API 请求。

接着做三个对照：同一时间打开一个普通网站和另一个 Google 服务；查看 Google Workspace 状态信息中心；在获准的环境中只用一个受支持浏览器或另一条合规网络复测一次。根据结果进入对应分支，仍无法定位就带着最小证据交给管理员或官方支持。

## 先花 1 分钟做"错误分流"

不要只记"Gemini 进不去"。请先抄下屏幕上的完整文字或代码，再对照下表：

| 你看到的内容 | 它至少说明什么 | 下一步 |
| --- | --- | --- |
| Gemini 页面内显示"请检查互联网连接，然后重试""出了点问题"等 | Gemini Web 已经渲染，但请求或会话没有正常完成 | 查状态、账号资格、Workspace 权限和浏览器对照 |
| Chrome 显示 `ERR_CONNECTION_CLOSED`、`ERR_CONNECTION_RESET`、`ERR_NAME_NOT_RESOLVED` 等 | 浏览器在打开页面时遇到传输、解析或响应问题 | 按 Chrome 错误码排查，不要直接判定 Gemini 宕机 |
| Gemini Android/iOS App 内提示无法连接 | 问题属于移动 App、账号、设备、商店或当前网络路径之一 | 核对 App 的独立可用范围和设备要求 |
| 程序返回 HTTP 状态、JSON 错误体或 SDK 异常 | 这是 AI Studio/Gemini API 开发者问题 | 保留请求证据，转到官方 API 故障排除 |

同一句中文转述可能对应不同原始错误。尤其不要把浏览器错误页写成"Gemini 返回 403"，也不要把 App 的重试提示当成 API 429。

## 情况一：Gemini 网页已经打开，但对话提示重试

### 1. 记录时间，再看官方状态

记录错误发生的日期、时间和时区，然后查看状态信息中心的 Gemini 行。本文复核时，页面在 **2026 年 7 月 21 日 18:02 UTC** 显示"无事故"；这只是当时的快照，你遇错时仍需重新查看。

状态页为绿色，不等于问题一定在你本地；状态页列出事故，也不能证明每个账号和每种 Gemini 表面都受影响。它只回答"Google 当前是否公开记录了服务事件"这一层问题。

### 2. 做一次有限对照

依次确认：

1.  普通网站是否可以打开；
2.  另一个 Google 服务是否可以打开；
3.  在组织允许的前提下，能否用 [Google 列出的受支持浏览器](https://support.google.com/gemini/answer/13278668?hl=zh-Hans) 复现；
4.  在允许使用的第二条网络上是否出现完全相同的提示。

一次对照就够了。若所有站点都失败，先处理设备或网络连接；若只有 Gemini 失败，继续检查状态、账号和 Workspace 条件。若问题只发生在某个浏览器配置中，可以临时用隐私窗口测试扩展或站点数据是否参与了故障；测试结果只能缩小范围，不能证明根因。

如果 Chrome 同时显示证书、HSTS 或"连接不是私密连接"警告，停止操作，不要绕过警告，也不要自行安装来源不明的证书。工作或学校设备应交给 IT 管理员。

### 3. 区分账号资格与连接故障

[Gemini 登录条件](https://support.google.com/gemini/answer/13278668?hl=zh-Hans) 会按账号类型区分个人、工作和学校账号，并要求使用支持的浏览器。若页面明确显示"无法访问此服务"或账号无法访问，优先核对账号类型、年龄条件和组织权限，而不是反复刷新。

请保持账号资料真实。修改出生日期、地址、国家或组织信息不是连接修复，也可能引入额外的安全与合规问题。

## 中国大陆用户必须看懂"仅限 Workspace"

截至 2026 年 7 月 22 日，Google 的 [Gemini Web 支持国家和地区](https://support.google.com/gemini/answer/13575153?hl=zh-Hans) 将"中国大陆"列为"**仅限 Workspace**"。这句话的准确含义是：官方 Web 可用范围为中国大陆列出了 Workspace 条件；**它不能被解读为个人消费者账号在中国大陆普遍受支持**。

还要注意两点：

-   "支持简体中文"是语言事实，不等于某个国家、账号或表面可用；
-   Web、移动 App、AI Studio 和 Gemini API 各有自己的地区与资格清单，不能互相套用。

如果你使用公司或学校账号，请让管理员核对组织是否允许访问 Gemini 应用、你所在的组织部门或访问群组是否已启用，以及所需许可是否适用。[Google Workspace 管理员帮助](https://support.google.com/a/answer/15293691?hl=zh-Hans) 说明管理员可以按组织部门或访问群组控制相关访问，而且设置变更可能需要时间生效。

如果你使用个人账号，官方 Web 清单里的"仅限 Workspace"没有为个人账号提供肯定答案。此时应停止把连接参数当作修复目标，转而核对官方地区说明或联系 Google 支持；不要通过修改账号身份资料来制造"符合条件"的外观。

## 情况二：Chrome 显示"意外终止了连接"

`ERR_CONNECTION_CLOSED`、`ERR_CONNECTION_RESET`、`ERR_CONNECTION_TIMED_OUT` 和 `ERR_NAME_NOT_RESOLVED` 不是同一个问题。Google 的 [Chrome 常见错误说明](https://support.google.com/chrome/answer/95669?hl=zh-Hans) 将它们分别归入连接被关闭或重置、超时、主机名解析等类别。

按这个顺序处理：

1.  复制完整错误码，而不是只截"无法访问此网站"；
2.  检查设备是否能打开其他网站；
3.  重新加载一次，必要时重启浏览器；
4.  在受支持浏览器或隐私窗口复测一次，用于判断扩展和站点数据是否相关；
5.  如果是受管理设备、企业网络或证书错误，把错误码交给管理员。

若隐私窗口可用，才有理由进一步检查扩展或清理 Gemini 相关站点数据。清理站点数据会退出登录，也不会改变账号、地区或服务端资格。若多个浏览器和允许的网络都在同一时刻出现相同失败，保留对照结果，转查官方状态或发送反馈。

## 情况三：Gemini 移动 App 无法连接

移动 App 不是 Web 的"手机版清单"。先查看 [Gemini 移动应用的提供情况](https://support.google.com/gemini/answer/14579026?co=GENIE.Platform%3DAndroid&hl=zh-Hans)，核对当前国家/地区、商店、账号、语言和设备是否都符合要求。

对 Android，本文复核到的官方要求包括 Android 9 或更高版本、至少 2 GB RAM；工作或学校账号还需要 Gemini 应用访问权限，并且 Gemini 移动应用不能在 Android 工作资料中访问。这些条件会变化，遇错时应以当前页面为准。

可以做的低风险检查包括：

-   记录 App 内完整提示、App 版本、系统版本和账号类型；
-   确认其他 App 能否联网，并在允许的第二条网络上复测一次；
-   从官方应用商店检查更新；
-   关闭并重新打开 App，必要时重启设备；
-   工作/学校账号直接询问管理员是否有访问权限。

如果 App 商店没有提供 Gemini，或官方国家/地区清单不覆盖你的使用场景，这不是"清缓存"能够改变的条件。不要安装来源不明的安装包。

## 情况四：你实际遇到的是 Gemini API 错误

只有在程序、AI Studio 或 SDK 返回了真实 HTTP 状态或结构化错误时，才进入 API 分支。请先保存：

-   HTTP 状态与完整错误体（删除密钥和令牌）；
-   模型、端点和 API 版本；
-   项目标识、时间与时区；
-   可复现问题的最小请求；
-   SDK 名称与版本。

[Gemini API 官方故障排除](https://ai.google.dev/gemini-api/docs/troubleshooting?hl=zh-CN) 对 `400`、`403`、`429`、`5xx` 等状态给出了不同含义。只有真实的 `429`、`408` 或 `5xx` 瞬时错误才适合有限次数的指数退避并加入随机抖动；`400` 和 `403` 通常要修正请求、权限、账号、地区或计费条件，盲目重试不会解决问题。

消费者页面里的"请重试"不能映射为任意 API 状态。反过来，API 的 `403 PERMISSION_DENIED` 也不能用于解释 Gemini App 的连接提示。

## 仍未恢复：把这份最小证据交给正确的人

建议复制下面的模板，填完后发给 Workspace 管理员、Google 支持或开发团队：

```text
表面：Gemini Web / Chrome 错误页 / Android App / iOS App / API
完整提示或代码：
发生时间与时区：
账号类型：个人 / 工作 / 学校（不要写邮箱）
浏览器或 App 版本：
设备与系统版本：
网络类别：家庭 / 移动数据 / 公司或学校（不要写公网地址）
官方状态页当时显示：
一次对照结果：普通网站、另一个 Google 服务、受支持浏览器或允许的第二网络
最小复现步骤：
```

不要在截图或日志中包含 API 密钥、Cookie、访问令牌、私人提示、上传文件或无关账号信息。已登录的 Web 用户可按 Google 当前界面进入"设置和帮助"→"发送反馈"，并选择是否附上截图。Google 的 [反馈说明](https://support.google.com/gemini/answer/13275746?hl=zh-Hans) 提醒：相关对话、上传内容或关联应用取得的个人内容可能随反馈一并收集，因此发送前应删去不必要的私人信息。

## 什么时候应该停止继续尝试

出现以下任一情况，就应该停止改设置并转交：

-   官方清单显示当前账号、地区、设备或表面不满足条件；
-   工作/学校账号需要管理员授权；
-   浏览器出现证书或安全警告；
-   多个受支持浏览器和允许的网络都在同一时刻复现；
-   API 返回持续的 `400` 或 `403`；
-   你已经完成一次有限对照，结果没有变化。

止损点很重要：重复更改账号、安全或地区相关设置，会污染原本清晰的故障证据，也可能带来新的账号风险。

## 常见问题

### 其他网站都能打开，为什么 Gemini 仍提示检查网络？

这只能说明设备并非完全离线。Gemini 的特定请求、浏览器配置、账号资格、Workspace 权限或某个时间点的服务事件仍可能失败。请记录表面和原始提示，再做一次官方状态与受支持浏览器对照。

### 官方状态页是绿色，能否确定是我的网络问题？

不能。绿色表示状态页在那个时间点没有公开列出事故，不代表所有用户、地区、账号和产品表面都正常。

### 中国大陆个人账号能否根据"仅限 Workspace"访问 Gemini Web？

"仅限 Workspace"没有为个人消费者账号提供支持承诺。个人账号应以 Google 当前官方 Web 地区说明为准，不要把支持中文误解为支持某个地区，也不要修改账号资料来规避资格判断。

### 无痕窗口能打开，是否证明只是缓存问题？

不能直接证明。它说明普通窗口里的站点数据、扩展或会话状态可能参与了问题。接下来应逐项缩小范围，而不是清除所有数据或推断地区判断已经改变。

### App 能用而 Web 不能用，或者反过来，矛盾吗？

不矛盾。Web 和移动 App 有不同的国家/地区、账号、设备和商店条件；一个表面的结果不能替另一个表面下结论。

### API 返回 403，继续重试会好吗？

通常不会。官方将 `403` 归为权限类问题，应检查密钥、权限、认证和适用条件。只有明确的瞬时错误才适合有限退避重试。

## 结论

处理 Gemini"无法连接服务器"的关键不是收集更多所谓技巧，而是保留原始错误并走对分支：Web 看状态、账号与 Workspace；Chrome 看传输错误码；App 看独立可用范围和设备；API 看真实 HTTP 状态。对中国大陆读者，Web 清单中的"仅限 Workspace"是必须保留的边界，不是个人消费者支持或绕行建议。

完成一次有限对照后仍无法定位，就把最小证据交给官方支持、Workspace 管理员或 API 开发负责人。这样比反复改动账号和安全设置更快，也更容易得到可验证的答案。
