## 先说结论：它解决的是“写完以后还要排版几次”

很多人的内容工作流是：在 Obsidian 写 Markdown，复制到另一个编辑器，再重新处理标题、行距、引用、代码、图片和封面，最后还要分别准备不同平台的格式。

Qiaomu Publish 把预览和交付留在 Obsidian 里：

```text
Obsidian Markdown → 实时预览与按篇排版
                 → 复制格式 / 导出文件 / 发送草稿 / 浏览器交接
                 → 由作者在目标平台检查并最终发布
```

它的核心价值不是自动替你发内容，而是把同一份内容的多次排版和交接收敛成一个工作流。笔记仍保存在自己的库中，排版设置可以按笔记保留，后续修改不需要从头开始。

## 一、适合谁

- 用 Obsidian 长期写公众号文章的作者；
- 整理读书笔记、知识卡片和课程内容的创作者；
- 经常分享代码、公式、表格、Mermaid 图和长文的人；
- 同一份内容需要准备公众号、X、知乎或小红书版本的团队。

如果只写纯文本、从不调整格式，也不需要导出或多平台交接，它带来的收益会比较有限。

## 二、安装与最短成功路径

README 要求 Obsidian **1.11.4 或更高版本**。最短路径是：

1. 打开 [Obsidian 官方社区安装页](https://community.obsidian.md/plugins/qiaomu-publish)；
2. 点击 **Add to Obsidian**，在 Obsidian 中安装并启用；
3. 打开一篇笔记，在命令面板运行“实时预览当前笔记的公众号排版”；
4. 先使用本地预览、排版、复制和导出功能；
5. 需要发送草稿时，再配置对应平台的连接和权限。

也可以在 Obsidian 的“设置 → 第三方插件 → 浏览”中搜索 `Qiaomu Publish`。手动安装是备用路径，需要从 [GitHub Releases](https://github.com/joeseesun/qiaomu-publish/releases/latest) 下载同一版本的 `main.js`、`manifest.json` 和 `styles.css`。

一个重要设计是：**不连接公众号也能先用**。预览、调整排版、复制格式和导出都可以先在本地完成，账号连接只在发送草稿时需要。

## 三、实时预览：写作和排版保持在同一窗口

### 1. 42 个内置主题

项目提供 42 个可搜索主题，从温暖的阅读风格，到简洁的技术文档和深色排版。主题会同时影响正文、列表、引用、表格和代码，预览会随着笔记修改并支持同步滚动。

### 2. 每篇笔记独立保存排版

工具栏中的 `T` 面板可以调整正文字号、字体、行距、段落间距、左右留白、首行缩进、代码配色、行号、图片说明、链接脚注和自定义 CSS。

这些设置保存在插件中，只作用于当前笔记，不会改写正文和笔记属性。重命名笔记或文件夹时，排版设置也会跟随保留。

## 四、封面、图片与导出

没有配图的笔记可以生成标题封面，单独设置更短的封面文字、背景、字体、字号和颜色。有图片时，插件优先使用笔记的 `cover` / `封面` 属性，否则选取正文第一张图片。

项目支持 Obsidian 图片嵌入、Markdown 行内与引用式图片、库内 HTML 图片和嵌入笔记附件，也支持代码高亮、MathJax 公式和 Mermaid 图转成图片。

相同附件重复引用时只上传一次。找不到的图片会阻止复制、导出和发送，并提示修正引用；动画 SVG 会明确报错，需要先转换为目标平台支持的格式。公众号正文图片接口在 README 中只承诺 JPG / PNG，GIF 的实际接受情况仍需在目标平台核对。

交付方式包括：

- **复制公众号格式**：复制带内联样式的内容，粘贴后仍需检查图片；
- **发送公众号草稿**：通过选定连接上传正文图片和封面；
- **导出 HTML**：带内联样式和嵌入图片，适合保存与分享；
- **导出长图 PNG**：适合预览，过长文章会降低分辨率并提示。

## 五、多平台交接：X、知乎和小红书

桌面版发布窗口可以切换平台，但需要同一台电脑的 Chrome 安装 **Qiaomu Clipper 1.18.7 或更高版本**，并登录所选平台。

| 平台 | 插件准备的内容 | 交接后的状态 |
| --- | --- | --- |
| X 文章 | 可编辑 Markdown、正文图片和封面 | 写入文章编辑器，检查后由用户发布 |
| 知乎 | 标题、正文、图片和题图 | 创建文章草稿，检查后由用户发布 |
| 小红书 | 3:4 图文卡片、标题、正文和话题 | 预填创作平台，检查后暂存或发布 |

封面可以从本机或笔记图片中选择、裁剪，也可以生成文字封面。小红书内容会变成静态图文卡片，GIF 动画不会保留在卡片中；X 和知乎的 GIF 在大小限制内可以保留，超限时会提示压缩，不会悄悄转换成 JPEG。

浏览器交接不是自动公开发布：插件会打开系统默认浏览器，将内容交给已经登录的平台页面，用户仍需检查并点击最终发布。若 Clipper 在另一个浏览器中，可以复制链接，粘贴到已安装扩展且已登录的平台浏览器。

## 六、公众号连接与凭据边界

发送草稿需要公众号 AppID、AppSecret、接口权限和正确的 API IP 白名单。README 列出三种连接方式：

| 连接方式 | 适合场景 | 主要准备工作 |
| --- | --- | --- |
| 固定 IP 的乔木中转 | 减少换网络后重配白名单 | 按插件显示的出口 IP 配置白名单 |
| 当前设备直连 | 直接调用微信接口 | 将当前设备公网出口 IP 加入白名单 |
| 自建 qmblog Bridge | 已有 Bridge 部署 | 配置 Bridge 地址和访问令牌 |

笔记和排版设置留在本地库，AppSecret 与 Bridge 令牌使用 Obsidian SecretStorage，不写进同步的插件 `data.json`。可选的乔木中转会接收 AppID、AppSecret 和发布内容，并通过 HTTPS 调用微信 API。

X、知乎和小红书交接时，插件会在 `127.0.0.1` 临时开启随机端口，由 Clipper 使用一次性凭证取得正文和图片；任务结束后端口关闭。等待中的交接链接不要分享。

## 七、网络、隐私和平台限制

纯本地文字排版不需要网络，但预览或导出远程图片、刷新白名单 IP、测试公众号连接、读取 Bridge 账号、打开二维码和通过中转或浏览器扩展交接内容都会联网。

对含有客户资料、内部文档或未公开研究的笔记，应先确认目标平台、连接方式和图片请求范围，再决定是否上传。插件只准备公众号草稿或平台编辑内容，不代替用户公开发布；音视频和网页嵌入也需要在公众号后台手动补充。

## 八、验证状态：本地受控服务不等于真实投递

项目 README 记录的 0.2.0 验证包括隔离 macOS Obsidian 中的预览、浅深色主题、窄面板、键盘调节、设置持久化、真实文件导出和从 0.1.2 升级后的设置保留。

草稿创建、更新和笔记写回使用本地受控服务验证；README 明确提醒，这不等同于真实微信账号验收，iOS / Android 真机也尚未覆盖。

项目的开发检查命令是：

```bash
npm ci
npm run check
npm run dev
```

安装后仍应在自己的账号、网络、白名单和目标平台中做一次小范围试发，检查图片、封面、标题、格式、草稿更新和最终发布效果。

## 九、适合落地的最小工作流

1. 在 Obsidian 写一篇不含敏感资料的测试文章；
2. 使用实时预览选择主题并调整排版；
3. 检查本地图片、代码、公式和 Mermaid 图；
4. 先导出 HTML 或 PNG，确认本地交付链路；
5. 再连接一个公众号或一个浏览器平台，发送测试草稿；
6. 检查目标平台中的图片、封面、标题和格式；
7. 最后再处理真实文章，并保留人工发布前的检查步骤。
