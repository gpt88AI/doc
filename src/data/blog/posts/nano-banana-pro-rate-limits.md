Nano Banana Pro 冷却先不要按一个统一倒计时处理。真正决定下一步的是入口：Gemini 应用、AI Mode、Gemini API、Flow 和第三方封装各自有不同的限额归属、重置方式和可接受的恢复动作。

| 冷却出现在哪里 | 谁负责重置或放行                                | 第一动作                                                                           |
|----------------|-------------------------------------------------|------------------------------------------------------------------------------------|
| Gemini 应用    | 当前 Google 账号、应用入口和方案下的图像限额    | 先确认同一账号、同一方案和界面提示，再等待刷新，或在界面提供时使用 Nano Banana 2。 |
| AI Mode        | Google 搜索 AI Mode 的图像生成限额              | 减少生成次数或等待每日图像限额刷新，不要先排查 API key。                           |
| Gemini API     | AI Studio / Google Cloud 项目下的 RPM、TPM、RPD | 查看项目、模型 ID、错误正文和 AI Studio 当前限额；RPD 按太平洋时间午夜重置。       |
| Flow           | Flow 的项目状态、credits、队列和可用入口        | 先看项目 credits 与任务队列，不要用盲目重试消耗额度。                              |
| 第三方封装     | 服务商自己的队列、节流、账号策略或上游失败处理  | 要求服务商提供时间戳、请求编号、上游响应类型，再判断是否是 Google 侧限额。         |

停止规则：不要通过换账号、轮换 API key、反复开新服务商来绕过冷却。安全动作是等待、使用允许的回退、缩小批量、排队、查看 AI Studio，或带着可复现证据升级处理。

## 快速判断冷却属于哪条入口

冷却是症状，不是一个独立产品模式。它可能代表消费者应用的每日图像限额、AI Mode 的会话限额、API 项目的速率压力、Flow credits 消耗、预览模型容量控制，或者第三方封装的排队策略。最快的排查方式是保持入口不变，先读清楚提示语，而不是同时改账号、改提示词、改浏览器、改密钥、换服务商。

<img src="/docs/blog/zh/nano-banana-pro-rate-limits/img/reset-owner-map.webp" class="blog-content-image cursor-zoom-in transition-opacity group-hover:opacity-90" loading="lazy" alt="Gemini 应用、AI Mode、API、Flow 和第三方封装的重置归属图" />

如果提示出现在 Gemini 应用里，就从应用入口查起。如果提示出现在 Google 搜索的 AI Mode 里，就按 AI Mode 图像限额处理。如果代码返回 HTTP 429、`RESOURCE_EXHAUSTED` 或类似速率限制信息，就进入 API 项目限额分支。如果第三方封装显示 cooldown、rate limit、queue、credits 或生成排队，那么第一责任人是该服务商，除非它能给出上游响应证据。

这个分流能避免两个常见误判。第一，购买消费者方案不等于 API 配额自动提高；第二，API 项目开通计费不等于 Gemini 应用或 AI Mode 的每日图像限额消失。它们可能共享模型名，却不共享一个重置时钟。

## Gemini 应用里的冷却和 Pro 重新生成

在 Gemini 应用里，Google 当前帮助页把普通图像生成和 Pro 重新生成分成两层。Gemini 应用的图像生成帮助说明，常规图像生成会使用 Nano Banana 2；符合条件的付费订阅者可以在部分输出上用 Nano Banana Pro 重新生成。Gemini 应用限额页面也说明图像限额会每日重置，并且可能频繁调整。

这意味着应用里的冷却不一定代表 Nano Banana Pro 整体宕机。它可能只是当前账号在这个入口耗尽了每日图像额度，Pro 重新生成选项暂时不可用，或者界面把后续请求切回 Nano Banana 2。只要界面明确提供 Nano Banana 2 作为回退，就可以把它用于草稿、低优先级变体或不需要最终质感的图像，而不是继续冲击 Pro 入口。

可以做一个有边界的应用检查：

| 检查项                                             | 为什么要看                               | 什么时候停止                   |
|----------------------------------------------------|------------------------------------------|--------------------------------|
| 确认 Gemini 显示的 Google 账号和方案               | 限额可能跟账号、地区、Workspace 状态有关 | 记录账号状态前不要来回切账号。 |
| 在新聊天里尝试一个短图像任务                       | 区分单个聊天卡住和入口限额               | 同一路径只重试一次。           |
| 查看是否出现 Nano Banana 2 回退或 Pro 重新生成字样 | 回退可能是系统允许的下一步               | 不要把回退直接当成全站故障。   |
| 如果问题在手机上出现，再用同一账号的网页版对照     | 区分移动端状态和账号级限额               | 不要在网页对照前反复卸载应用。 |

如果同一账号、同一入口、同一简短任务仍然显示冷却，接下来有用的不是继续改提示词，而是保存提示截图、时间、入口、账号方案、是否出现 Nano Banana 2 回退，以及是否只有某个端失败。这些信息比“我还有付费方案”更能帮助支持人员判断。

## AI Mode 图像限制是另一条线路

AI Mode 不是 Gemini 应用，也不是 Gemini API。Google 搜索的 AI Mode 图像创建帮助把图像生成限制绑定到当前 AI Mode 体验和计划状态；达到限制后，用户通常需要等待刷新，或使用允许的计划路径。

所以如果冷却出现在搜索侧或 AI Mode 对话里，不要先去改 API key。先在 AI Mode 里确认账号、方案、图像入口、可见提示，以及当前会话是否明确要求等待。如果任务很急，先降低需求：减少变体数量、一次生成一张、简化编辑指令，或把不重要的图像转到其他允许入口。

AI Mode 的提示有时不会以完全相同的 Nano Banana Pro 文案出现。它可能只说已经达到限制、需要稍后再试、或当前图像请求不可用。只要问题发生在搜索侧，就先当成 AI Mode 图像限额，直到同一账号、同一时间窗口、同一任务也在其他 Google 自有入口失败，才把范围扩大。

## Gemini API 冷却通常是项目限额

开发者遇到 Nano Banana Pro 冷却时，真正要查的是 API 项目限额、速率压力、预览模型容量，或请求形状消耗过快。Gemini API 的速率限制文档把限额拆成 RPM、TPM、RPD，并要求开发者到 AI Studio 查看当前项目限额。每日 RPD 属于 API 项目，按太平洋时间午夜重置，不跟消费者应用本地界面刷新同步。

API 模型身份也要分开看。当前 Pro 图像 API 模型使用 `gemini-3-pro-image-preview` 这样的模型 ID。这个 ID 只说明 API 调用对象，不说明 Google AI Pro 或 Ultra 订阅会提高 API RPM、TPM、RPD。API 配额看项目、账单、用量层级、区域、模型和 AI Studio 显示的当前限额。

代码触发限制时，先分类再重试：

| API 线索                                        | 可能归属                            | 第一检查                                    | 重试规则                           |
|-------------------------------------------------|-------------------------------------|---------------------------------------------|------------------------------------|
| HTTP 429、`RESOURCE_EXHAUSTED`、rate-limit 文案 | API 项目额度或速率压力              | AI Studio 当前限额、模型 ID、项目、请求时间 | 只有加退避或排队后才重试。         |
| RPD 用尽                                        | 每日项目配额                        | AI Studio RPD 和太平洋时间午夜重置          | 当天不要继续盲打，除非限额已变化。 |
| 只有一个项目或一个 key 失败                     | 项目、key、账单、模型权限或区域问题 | 项目选择、账单状态、模型可用性              | 先修作用域，不要先改业务代码。     |
| 第三方封装返回泛化 cooldown                     | 服务商节流或队列                    | 服务商请求日志、上游响应、状态页            | 先要证据，再判断 Google API。      |

不要通过轮换 API key 绕过项目限额。这样会破坏日志归属，掩盖真正瓶颈，也可能带来策略风险。更稳的生产做法是队列、每项目并发控制、提示词负载控制、缓存复用，以及在 RPD 用尽时给用户清晰的稍后重试状态。

## 为什么付费用户也会遇到较低上限

付费访问不等于无限 Pro 图像容量。Google 的帮助语言保留了每日限额变化、高需求容量控制、计划差异、账号状态和入口差异。社区里关于“付费用户不到预期次数就被挡住”的说法可以解释大家为什么搜索冷却，但不应被写成当前官方数字。

<img src="/docs/blog/zh/nano-banana-pro-rate-limits/img/paid-user-cooldown-diagnosis.webp" class="blog-content-image cursor-zoom-in transition-opacity group-hover:opacity-90" loading="lazy" alt="付费用户遇到 Nano Banana Pro 冷却时的排查图" />

付费用户可以先按这个分支判断：

| 原因                        | 表现                                          | 处理                                                      |
|-----------------------------|-----------------------------------------------|-----------------------------------------------------------|
| 高需求或临时容量控制        | Pro 选项存在，但比预期更早停下                | 等待刷新，减少批量，或把非最终图像交给 Nano Banana 2。    |
| 入口弄错                    | Gemini 应用付费用户以为 API 配额也会增加      | 到 AI Studio 查看 API 限额；应用方案和 API 项目是两回事。 |
| 账号、地区或 Workspace 状态 | 一个账号能用，另一个账号不稳定                | 记录账号、地区、Workspace 管理状态和可见方案文案。        |
| 提示负载太重                | 大批量、重编辑、多轮变体很快消耗额度          | 拆小任务，复用接近目标的输出，减少重复变体。              |
| 第三方封装排队              | 服务商说 cooldown，但 Google 直接入口表现不同 | 要求请求编号、时间戳和上游响应类型。                      |

最重要的判断是，不要把“我付费了”当成“Pro 图像无限”。付费方案可以改善入口，但仍可能有每日限额、容量控制、账号状态、地区可用性、工作区策略和入口差异。

## 需要马上出图时怎么处理

冷却挡住实际工作时，选择既保护账号又能推进任务的动作。目标不是打穿限制，而是在不制造新故障的前提下完成图像工作。

<img src="/docs/blog/zh/nano-banana-pro-rate-limits/img/safe-recovery-ladder.webp" class="blog-content-image cursor-zoom-in transition-opacity group-hover:opacity-90" loading="lazy" alt="Nano Banana Pro 冷却后的安全恢复阶梯" />

建议按这个顺序做：

1.  先分类入口：Gemini 应用、AI Mode、Gemini API、Flow，还是第三方封装。
2.  读原始提示：每日限额、回退、节流、队列、credits、项目配额，还是功能不可用。
3.  使用允许回退：Nano Banana 2、小批量、稍后重试、排队、或低优先级入口。
4.  API 工作先查 AI Studio，再改代码。
5.  付费消费者账号先确认可见方案和入口归属，再判断是否故障。
6.  升级时带证据：入口、时间、截图、请求编号、提示类别、账号/方案表面，以及其他入口是否成功。

如果确认是纯 API 429 分支，后续重点应转向 API 速率限制、重试退避、队列和项目配额。如果问题是价格、免费额度或模型选择，就把它从冷却排障里拆出去，单独按 API 价格和模型路线处理。这样冷却页才能专注于恢复动作，而不是变成泛化目录。

## 不建议做什么

不要把“绕过限制”当成修复方案。换账号、轮换 key、滥用试用、并行硬打，都会增加账号风险，也会让原始失败更难追踪。盲目重试还会浪费 API 额度，把本来可恢复的 RPM 压力变成更长的队列问题。

不要把 Reddit、Threads、Facebook 或其他论坛里的次数当成官方限额。那些讨论有价值，是因为它们暴露了真实用户语言：付费用户遇到更低上限、Ultra 也可能等待、AI Mode 和 Gemini 应用表现不同、第三方服务商会有自己的冷却提示。但你自己的下一步仍然要看当前入口和官方归属。

也不要把旧的 Free / Pro / Ultra / API 固定矩阵放在首屏。固定数字很快过期，并且会混淆消费者应用、AI Mode、API、Flow 和封装服务。更稳定的问题是：冷却出现在哪里，谁拥有重置，当前最小安全动作是什么。

## 常见问题

### Nano Banana Pro 冷却一般多久？

没有一个通用的 Nano Banana Pro 冷却时长。Gemini 应用和 AI Mode 使用会变化的每日图像限额；Gemini API 的 RPD 按太平洋时间午夜重置；第三方封装的冷却取决于服务商队列和策略。

### Nano Banana Pro 是每天重置吗？

消费者 Google 入口的帮助页描述了每日重置且可能变化的图像限额。Gemini API 的 RPD 是每日项目配额，按太平洋时间午夜重置；RPM 和 TPM 更像速率窗口，属于 API 项目而不是应用订阅。

### 为什么 Gemini 会回到 Nano Banana 2？

在 Gemini 应用里，Nano Banana 2 可能是常规图像生成入口，而 Nano Banana Pro 是符合条件用户可用的重新生成入口。Pro 路径耗尽或暂不可用时，Nano Banana 2 可能是允许回退，而不一定是故障。

### Google AI Pro 或 Ultra 会取消所有冷却吗？

不会。付费访问可以提高某些入口的可用性，但不等于无限 Pro 图像容量。每日限额、容量、地区、账号、Workspace 管理和入口差异仍然会影响结果。

### Pro 订阅会提高 Gemini API 配额吗？

不会自动提高。消费者订阅和 Gemini API 是不同线路。API 配额跟 Google Cloud 或 AI Studio 项目、账单层级、模型、RPM、TPM、RPD 和当前项目限制有关。

### 可以绕过 Nano Banana Pro 冷却吗？

不要通过换账号、轮换 key 或换服务商来绕过。安全替代是等待正确重置、使用界面允许的 Nano Banana 2、降低批量、排队 API 工作、检查 AI Studio 限额，或带证据升级。

### 为什么网上有人说每日次数完全不同？

用户报告通常混合了入口、地区、账号、计划、需求高峰和封装服务。它们能解释为什么大家会说“冷却”“限制”“降级”，但不能替代你当前账号和入口的可见提示。

### 什么时候应该联系支持？

同一路径做过一次干净验证仍失败，并且能提供入口、时间、账号/方案表面、可见提示、截图、请求编号、提示类别和其他入口对照结果时，再联系 Google 支持或服务商支持。证据越具体，越容易分清是账号限额、项目限额还是服务商队列。
