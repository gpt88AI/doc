### FPV Ventures 合伙人 Nikunj Kothari

Nikunj Kothari 质疑用 benchmark 作为模型优越性的展示方式：真正重要的是把模型放进自己的 workflow，观察哪些模型实际有效。他认为少数 benchmark 有参考价值，但大量榜单更像营销或围绕单一指标的 hill climbing，不能替代真实使用。

### Training Data：A Model For Everyone: How Ronak From Trajectory Is Building Products For Continual Learning

**一句话结论：** Trajectory 想把生产中的 agent traces、对“什么是好结果”的定义、模型训练、eval 和部署放进一个闭环，让每家公司都能用自己的经验持续改进模型。

Trajectory 联合创始人 Ronak 把当前的 AI 描述为“伪持续学习”：模型很强，但通常只能离线批量更新；真正的 continual learning 应该像 Google Maps 一样，在每次实际使用后吸收新的路线和反馈。Trajectory 的产品从 traces 开始，把生产中的 agent 行为 replay 到可控环境，再把 reward 和训练算法连接起来，目标是让企业不必拥有数百人的研究团队，也能把“什么是好结果”转化为模型改进。

一个具体案例是 Harvey：借助自己的法律数据、专家知识和 agent benchmark，它把开放模型的准确率从约 4% 提高到约 18%，同时模型成本约为 frontier model 的六分之一。Ronak 还介绍了两个研究方向：用 group size one 减少对重复环境的依赖，以及从少量代表性 traces 学习 meta grader，再把 reward 推广到更大的数据集。

他认为，长期目标不是让 agent 在黑箱里递归自我改进，而是让模型从与人互动的经验中学习，始终把人保持在 loop 中。产品层面则会从训练模型扩展到优化 harness：对高价值任务使用 frontier model，其余任务路由到更快、更便宜、经过定制的模型。正如他所说：“I want this basically paradigm to propagate, where the unit of work that we think about is a trajectory.”
