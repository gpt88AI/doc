### Box CEO Aaron Levie

Aaron Levie 预测，coding、tool use、computer use 和数学能力会继续提升，使能操作软件或从零生成代码的 agent 在知识工作中进步得更快。结果可能不是只有少数工作被自动化，而是更多工作会变成“coding-shaped”，因为 agent 可以通过生成软件或调用现有软件进入网络安全、生命科学和金融等领域。对模型的要求也不必是“知道一切”，而是把软件生成或使用能力与领域知识结合起来，在工作流中做出正确判断。

### Unsupervised Learning：Ep 97: Jev Creator on Decision Models, Benchmark Fatigue &amp; Why the Labs Missed It

**一句话结论：** JEV 的方向不是把模型包装成更会聊天的字符串生成器，而是推动 machine-native 的决策核心；要让它真正进入生产，还必须正视模型的 jaggedness，并让开发者参与定义所需的可靠性。

TypeSave CEO、JEV 创造者 Jogo 解释了为什么自己相信 AI 同时具备很高的智能，又在生产力指标上远没有兑现潜力：关键问题可能不在 distribution，而在模型输出仍主要为人类消费设计。对计算机来说，字符串通常不是理想接口；更自然的方向是让模型成为软件调用的认知核心，输出更接近机器可消费的结构。他说：“I don't think a computer really ever wants a string except when that string happens to be an extreme cardinality enum.”

Jogo 也强调，模型能力与使用场景需要共同演化。开发者比模型提供方更清楚下游应用需要怎样的 reliability、robustness 和 intelligence，因此应该获得足够的 knobs 去探索模型的边界。JEV 目前仍然不够稳定，团队把“jaggedness”视为需要持续调试的问题，而不是用一个 benchmark 分数掩盖它。

他反对把不同模型固定成一套僵硬的任务分类，认为长期目标应该像 SQL 一样可靠、provider agnostic。即使 RLVR 在 coding 和数学上很强，现实系统仍常常需要 human in the loop；模型在某些维度达到超人水平，不代表它已经理解了完整工作流。对开发者来说，短期可以用各种 hack 提供价值，但模型提供方最终仍应减少这些补丁，让能力更接近可复用的语义组件。
